【设计时间】2026-07-30

============================================================
【一、触发条件总览】
============================================================

  结局 | 触发条件                              | 优先级 | 触发时机
  ─────┼──────────────────────────────────────┼────────┼──────────
   C   | memory_zhi == 0                       | 最高   | 任何时候(强制中断)
   A   | 6 章全通 + total_size == 15           | 中     | 在 hall · 按 E 于 ✦
   B   | 6 章全通 + total_size <= 13(遗漏≥2) | 中     | 在 hall · 按 E 于 ✦

  说明:
    · C 是"任何时候都可能触发"的紧急结局
    · A/B 都需要"走到 hall 中央 · 按 E"来主动进入终章
    · A 和 B 由 total_size(拾取件数)自动分流
    · 玩家永远看不见"你现在会触发哪个"的提示

【二、结局 C · 记忆值归零触发】
============================================================

▌ 触发点
   现有代码中 · now_time() 返回 -1 时(见 源.cpp:146)
   主循环 while (!_kbhit()) 里 · temp == -1 时 · ending_c = 1

▌ 修改点
   源.cpp:1302-1313 现有的"结局 C 占位"要替换成真实调用:

   原代码:
     if (ending_c) {
         system("cls");
         setColor(12);
         gotoxy(30, 12);
         printemoji(L"结局 C 触发（占位）");
         ...
         break;
     }

   新代码:
     if (ending_c) {
         play_ending_C();   // 调用真正的结局 C
         break;
     }

▌ 特殊性
   · 强制中断:不管玩家在 hall 还是任何一个章场景 · 都立刻切
   · 不需要"确认"· 记忆值到 0 就直接进结局 C
   · C 的段 0 消散动画会先播 · 一开场就有强烈的"你完了"感

▌ 玩家心理
   · 玩家在游戏中看到记忆值 100 → 60 → 30 → 0
   · 记忆值系统本身已经暗示"你可能触发不好的结局"
   · 到 0 的瞬间 · 屏幕黑 · 消散动画开始 · 没有回头路

【三、结局 A/B · 在 hall 里触发】
============================================================

▌ 触发点
   玩家在 hall 中 · 6 个章节全通(pangbai_alredy[1..6] 都为 1)
   hall 中央出现新标志 ✦
   玩家走到 ✦ 面前(或站在附近)· 按 E · 触发终章

▌ 需要新增的东西

   1. hall.txt 布局不改(6 个 D 门保持)
   2. 代码里画:
      · ✦ 出现在 hall 中央(推荐 x=24 y=5)· 顶部星轨下方
      · ✦ 呼吸(色 8→7→6→14→6)· 复用主界面 begin_title 的做法
      · ✦ 下面显示"—— 终章 ——"三个字 · x=20 y=6 · 灰 8

   3. 触发条件检查:
      · 判定函数 all_chapter_done()
      · 只有 6 章都过了 · ✦ 才出现
      · 玩家走到 ✦ 附近(碰到 ✦ 或 (24, 6))· 按 E 触发

▌ 分流机制

   走到 ✦ 按 E 之后 · 代码判断 total_size:
     · total_size >= 15  → play_ending_A()
     · total_size <= 13  → play_ending_B()
     · total_size == 14  → play_ending_B()(算遗漏 ≥ 1)

   注意:
     · 三个隐藏物品 C 是"可以捡到 · 也可以遗漏"的
     · 全部 15 件 = 6 章 × (A+B+C) · 就是最完美的通关
     · 少于 15 件 · 都算 B

【五、finale_check() 分流函数】
============================================================

▌ 伪代码

  void finale_check(void) {
      // 玩家按 E 走到 ✦ · 分流三个结局
      // 注意 · C 已经在别处触发(记忆值归零)· 这里只处理 A/B

      // 关闭记忆值扣分(防止在结局动画中记忆值继续掉)
      memory_zhi = 999;    // 或 pause_memory()

      // 分流
      if (total_size >= 15) {
          play_ending_A();
      } else {
          play_ending_B();
      }
  }

▌ 分流逻辑图

  按 E · 判定
    │
    ├─ total_size >= 15  → 结局 A(4 场景 · 17:30)
    │
    └─ total_size <= 14  → 结局 B(1 场景 · 8 分钟)

  · 15 = 全部 6 章 · 每章 3 件 = 6 × 3 - 3(章 6 的可选)= 15
  · 或者是 6 章都 3/3 · 严格 6 × 3 - 3
  · 具体数字看 total_size 的实际最大值(检查代码 · 后面确认)

【六、all_chapter_done() 判定函数】
============================================================

▌ 伪代码

  int all_chapter_done(void) {
      // 只判断 pangbai_alredy[1..6]
      // pangbai_alredy[0] 是 hall 自己 · 不算
      for (int i = 1; i <= 6; i++) {
          if (pangbai_alredy[i] == 0) return 0;
      }
      return 1;
  }

▌ 简单可靠
   pangbai_alredy 数组每次玩家进入一个章场景就置 1
   6 章都进过 · 返回 1

【七、hall 主循环里的改动】
============================================================

▌ 关键改动 · 主循环 while (1) 内部

  1. 每次画 hall 时 · 检查 all_chapter_done()
     · 如果返回 1 · 画 ✦ 呼吸 + 提示

  2. 按 E 时 · 判断玩家位置
     · 如果 @ 在 (24, 6) · 且 all_chapter_done() · 触发 finale_check()

  3. 呼吸动画
     · 复用 while (!_kbhit()) 循环里的 Sleep(50) 时机
     · 每 8 次(400ms)推进一帧 ✦ 呼吸

▌ 伪代码 · 插入位置

  while (1) {
      if (strcmp(cursecene, "hall.txt") == 0 && all_chapter_done()) {
          draw_finale_marker();   // 画 ✦ + "—— 终章 ——"
      }

      // ...其他绘制...

      while (!_kbhit()) {
          Sleep(50);
          int temp = now_time();
          if (temp == -1) {
              ending_c = 1;
              break;
          }
          if (temp == 1) {
              draw_memory_secene();
          }

          // 新增:✦ 呼吸
          static int vega_frame_count = 0;
          if (strcmp(cursecene, "hall.txt") == 0 && all_chapter_done()) {
              vega_frame_count++;
              if (vega_frame_count >= 8) {
                  vega_frame_count = 0;
                  breathe_vega_marker();   // 推进一帧呼吸
              }
          }
      }

      // 按 E 触发结局
      if (c == 'e') {
          // ...现有的物品交互代码...

          // 新增:如果在 hall 中央 · 触发终章
          if (strcmp(cursecene, "hall.txt") == 0
              && px == 24 && py == 6
              && all_chapter_done()) {
              finale_check();
              break;
          }
      }
  }

【十、结局函数结束后的处理】
============================================================

▌ 三个选择

  选项 A · 直接退出程序
    play_ending_X() 结束后 · 主循环 break · main() 结束

  选项 B · 回主菜单
    play_ending_X() 结束后 · 调 begin_title() 回主界面
    · 更完整的游戏体验
    · 玩家可以再玩一次尝试其他结局

    献词播完后按空格 · main() 结束

  推荐:选项 B · 回主界面
    · 玩家可以重玩 · 尝试三个不同结局
    · 主界面显示"你已经通关了 X 结局"(可选)

【十一、防止记忆值在结局中扣分】
============================================================

▌ 问题
   记忆值扣分逻辑在 now_time() 里 · 每 Sleep(50) 触发
   如果结局动画期间 · 记忆值继续扣 · 会有 bug:
   · A 结局播到一半 · 记忆值到 0 · 触发 C(不应该)
   · B 结局同理

▌ 解决方案 · 结局函数一开始就冻结记忆值

  void play_ending_A(void) {
      memory_zhi = 999;   // 简单粗暴 · 永远扣不到 0
      // 或者:pause_memory() · 用之前的 push_stack_time 机制
      push_stack_time();

      // ... 结局播放 ...

      // 结局结束 · 不用 pop · 反正要退出主循环了
  }

▌ push_stack_time 已经存在
   代码中 · 章节过场和对话都用 push_stack_time 暂停记忆值
   结局函数直接沿用这个机制即可

【设计备注】
============================================================

▌ 触发点唯一 · 分流靠数据
   A/B 共用一个触发点(hall 的 ✦)· 靠 total_size 分流
   玩家不知道自己会触发哪个 —— 增加悬念

▌ C 不需要触发点
   C 是记忆值归零的"惩罚"· 随时可能来
   这个不确定性本身就是压力

▌ 玩家看不见判定条件
   代码里判定 pangbai_alredy 和 total_size · 玩家不知道具体数字
   ✦ 出现的一瞬间玩家才知道"哦 · 6 章都过了"
   拾取件数在 UI 上显示("拾取 X/3")· 但不会告诉玩家总数

▌ 三个结局互斥
   一次通关只走一个结局 · 触发一个后主循环 break
   如果玩家想看其他结局 · 需要重玩
