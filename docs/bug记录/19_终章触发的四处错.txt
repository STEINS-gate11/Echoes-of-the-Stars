============================================================
Bug 19 · 终章触发的四处错 · 一次写完全部踩坑
============================================================

【时间】2026-08-01
【严重程度】高 · 三个逻辑错 + 一个不调用
【位置】源.cpp hall_react / fenqi_AB / main 的 c == 'e' 分支

============================================================
【背景】
============================================================

  Hall 终章触发机制第一版写完后，四处都有问题。
  这四个错误分别是四种不同的类型，值得逐个记。

============================================================
【错 1 · 逻辑取反 —— 最隐蔽】
============================================================

  写的：

    int hall_react(int px, int py) {
        if (six_chapter_done()) {
            return 0;              // ← 完成了却返回 0
        }
        if (isreact(px, py, 24, 13)) {
            return 1;
        }
        ...
    }

  实际行为：
    6 章完成 → 立刻 return 0 → 永远进不去终章
    6 章没完成 → 继续判 isreact → 反而能进

  完全反了。

  为什么会写错：
    "如果六章做完了" 这个念头写出来自然是 if (six_chapter_done())
    但函数的守卫模式应该是 "如果没做完就走开"
    守卫（guard clause）永远是判否定条件

  修：
    if (!six_chapter_done()) {
        return 0;
    }

  ★ 教训：守卫子句一定带 !
    写守卫的时候先想"什么情况下要提前返回"，
    而不是"什么情况下是对的"

============================================================
【错 2 · 函数名当表达式 —— 编译器只给 warning】
============================================================

  写的：

    if (hall_react(px, py)) {
        fenqi_AB              // ← 没有括号，也没有分号后的 break
    }

  这不是调用函数，这是取函数地址然后丢掉。

  编译器行为：
    MSVC 可能只给 warning C4551（函数调用缺少参数列表）
    甚至在某些设置下什么都不报
    → 编译过，运行时什么都不发生

  这是最危险的一类错误：能编译，能运行，就是没效果。

  修：
    if (hall_react(px, py)) {
        fenqi_AB();
        break;
    }

  break 也必须加 —— 否则播完结局会掉进下面的 for 循环继续判门。

  ★ 教训：C++ 里函数名不加括号是合法表达式
    if (someFunc) 永远是 true（函数地址非空）
    看到 if 里只有一个标识符，先确认它是不是漏了括号

============================================================
【错 3 · 复制粘贴没改完 —— B 分支调了 A】
============================================================

  写的：

    if (total_size >= 18) {
        printemoji(L"—— 星光彼岸 ——");
        play_jieju_A();
    }
    else {
        printemoji(L"—— 遥远的暗星 ——");
        play_jieju_A();          // ← 应该是 play_jieju_B()
    }

  症状：
    两个分支都走 A 结局
    字幕显示"遥远的暗星"，播的是"星光彼岸"的内容
    B 结局永远播不到

  为什么会写错：
    else 分支是复制 if 分支改的
    改了字幕和颜色，忘了改函数名

  ★ 教训：复制粘贴的分支，改完要逐行对比
    特别是"只有一个词不同"的两段代码
    if/else 两边最容易漏

============================================================
【错 4 · 声明 int 但不返回值】
============================================================

  写的：

    int fenqi_AB() {
        ...
        if (...) { play_jieju_A(); }
        else { play_jieju_B(); }
    }                            // 没有 return

  编译器行为：
    MSVC: warning C4715 "不是所有的控件路径都返回值"
    GCC/Clang: warning: control reaches end of non-void function
    行为未定义 —— 返回栈上的垃圾值

  这个函数不需要返回值，本来就该是 void。

  修：
    void fenqi_AB() {

  ★ 教训：写函数先想返回类型
    "这个函数要告诉调用者什么" —— 没有就是 void
    不要习惯性写 int

============================================================
【四种错误类型对照】
============================================================

  ┌──────────────┬─────────────────┬──────────────────┐
  │ 错误          │ 编译器会说吗     │ 后果             │
  ├──────────────┼─────────────────┼──────────────────┤
  │ 逻辑取反      │ 不会            │ 功能完全反了     │
  │ 漏函数括号    │ 只给 warning    │ 静默无效果       │
  │ 分支调错函数  │ 不会            │ 走错流程         │
  │ int 不返回    │ 给 warning      │ 未定义行为       │
  └──────────────┴─────────────────┴──────────────────┘

  四个里面有两个编译器完全不管。
  这就是为什么写完必须自己走一遍逻辑，不能只看编译过没过。

============================================================
【怎么防】
============================================================

  1. 守卫子句写完，把条件念出来
     "如果没做完就返回 0" —— 念着对了才对

  2. if 里只有一个标识符 → 检查是不是漏括号

  3. if/else 两边逐行对比
     用编辑器分屏，或者干脆把 else 分支重写一遍不复制

  4. 函数写完先看返回类型对不对

  5. 打开所有 warning
     VS：项目属性 → C/C++ → 警告等级 → /W4
     C4551 和 C4715 在默认 /W3 下可能不显示
