============================================================
Bug 16 · play_A_tiantai_dubai 调用时缺 2 个参数
============================================================

【时间】2026-07-31
【严重程度】致命 · 编译不过
【位置】源.cpp play_jieju_A 倒数第 2 段

============================================================
【现象】
============================================================

  函数定义(3 个参数):

    void play_A_tiantai_dubai(const wchar_t* text, int delay1, int delay2) {
        ...
    }

  A 结局里 130 段独白,129 段都是对的:

    play_A_tiantai_dubai(L"果然，我的想法她一样——", 28, 400);      ← 对

  但最后一段少传了 2 个:

    play_A_tiantai_dubai(L"我想成为你的那颗星————");               ← 错

============================================================
【编译器报什么】
============================================================

  MSVC:
    error C2660: "play_A_tiantai_dubai": 函数不接受 1 个参数

  GCC/Clang:
    error: too few arguments to function 'play_A_tiantai_dubai'

  报错行号会直接指到那一行,很好找

============================================================
【为什么会写错】
============================================================

  这是 A 结局最后一句台词
  写到第 130 段的时候,手已经麻了
  前面 129 段都是复制粘贴改文字
  最后一段是新打的,忘了后面两个参数

  典型的"批量操作到最后一个出错"

============================================================
【修复】
============================================================

  错的:
    play_A_tiantai_dubai(L"我想成为你的那颗星————");

  对的:
    play_A_tiantai_dubai(L"我想成为你的那颗星————", 28, 400);

  delay1 = 28   —— 和其他 129 段一致
  delay2 = 400  —— 最后一句情绪重,给 400 毫秒

============================================================
【怎么防】
============================================================

  1. 批量写重复调用时,最后一个单独检查
     前面 N-1 个是复制的,格式一定对
     最后一个如果是新打的,大概率漏参数

  2. 编译一次比检查十遍快
     这种错误编译器 100% 抓得住
     不要靠肉眼扫

  3. 写完一大段就编译一次
     不要写完 130 段才编译
     写 20 段编译一次,错了立刻知道在哪 20 段里

============================================================

    else {

  结论:写代码的最后几行要慢一点
