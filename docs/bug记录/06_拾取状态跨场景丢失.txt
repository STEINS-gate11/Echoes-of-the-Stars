============================================================
Bug 06 · 拾取状态跨场景丢失（数据源不统一）
============================================================

【发生时间】2026-07-24
【严重程度】中


============================================================
【一、现象】
============================================================

玩家在章 1 (prologue) 拾取了 A（折纸星星）→ 按 Q 回 hall →
再从 hall 进入章 1，A 又出现在原来的位置，能再捡一次。

而且再捡后，对话历史链表里会出现"重复的⭐折纸星星"两条记录。

拾取计数右下角 "拾取: X/3" 也会重复算，可能超过 3。


============================================================
【二、定位过程】
============================================================

看 get_to_the_secene 函数：

  void get_to_the_secene(...) {
      system("cls");
      currentChapter = chapter;
      *flagA = 0; *flagB = 0; *flagC = 0;    // ← 就是这里
      ...
      load_secene(...);
  }

每次进场景都把 flag 全归零。也就是说：
  - 场景本身没记住"我之前进来时捡过什么"
  - load_secene 会重新把 A/B/C 画出来
  - 加上 flag 归零，玩家自然可以再捡一次

问：谁"记住"了玩家拾过什么？
答：链表 head → ... → tail 就记着（每次拾取 pushDialog 一条）

那问题变成：进场景时，flag 没从链表恢复。


============================================================
【三、根本原因】
============================================================

★ 数据源不统一。

  拾取信息有两份"记录"：
    1. 场景内的 flagA / flagB / flagC（当次进入场景的临时状态）
    2. 链表（全局历史）

  但两者从来没同步过：
    - 每次进场景，flag 归零
    - 链表不为空，但 flag 不查链表
    - 于是"链表已经有记录了"但"flag 说没捡过"，出现矛盾

  这是典型的【多源数据不同步】bug。


============================================================
【四、解决方案】
============================================================

★ 让链表成为【唯一数据源】。

  flag 不是独立记录，而是每次进场景时【从链表推导出来】。

修改 get_to_the_secene：

  void get_to_the_secene(...) {
      system("cls");
      currentChapter = chapter;

      // 【改】从链表查是否已拾取
      *flagA = isPicked(chapter, 0);
      *flagB = isPicked(chapter, 1);
      *flagC = isPicked(chapter, 2) ? 3 : 0;

      *px = 24; *py = 18;
      strcpy(curscene, difsecene[chapter - 1].text);
      load_secene(curscene, bg, ax, ay, bx, by, cx, cy);
      if (chapter < 6) game_begin_locked[chapter + 1] = 1;

      // 【新】根据 flag 抹掉已拾取的物品
      if (*flagA && *ax >= 0) {
          bg[*ay][*ax] = ' ';
          gotoxy(*ax, *ay); setColor(15); printf(" ");
      }
      if (*flagB && *bx >= 0) {
          bg[*by][*bx] = ' ';
          gotoxy(*bx, *by); setColor(15); printf(" ");
      }
      if (*flagC == 3 && *cx >= 0) {
          bg[*cy][*cx] = ' ';
          gotoxy(*cx, *cy); setColor(15); printf(" ");
      }
  }

新增 isPicked 函数（在 clearDialog 后）：

  int isPicked(int chapter, int slot) {
      const wchar_t* targetName = itemDialogs[chapter - 1][slot].name;
      DialogNode* p = head;
      while (p) {
          if (p->chapter == chapter && p->name == targetName) return 1;
          p = p->next;
      }
      return 0;
  }


============================================================
【五、教训】
============================================================

1. 【单一数据源】原则
   一个信息只应该有一处权威记录，其他地方从这里推导。
   比如"物品是否拾取"只由链表决定，flag 是【读时计算】出来的。

2. 【init 时同步】
   每次场景初始化，必须从权威数据源同步状态，不能全归零。

3. 数据流入 vs 数据流出：
   - 拾取时：flag=1 → pushDialog（状态流入链表）
   - 进场景：isPicked → 恢复 flag（状态流出链表）
   两个方向都要处理，否则会数据丢失。


============================================================
【六、举一反三】
============================================================

类似的"多源数据不同步"陷阱，还可能出现在：

  - 角色血量存了两份：变量 + UI 数字，改变量忘更新 UI
  - 章节解锁：locked 数组 + 门的显示颜色，一处改另一处忘
  - 配置文件：内存里的 config + 磁盘的 config.json，保存时忘写盘

防御思路：
  凡是"看起来在多处出现的信息"，问自己：
    - 权威源是谁？
    - 其他地方是【读时计算】还是【存了副本】？
    - 副本是不是每次都会从权威源刷新？
