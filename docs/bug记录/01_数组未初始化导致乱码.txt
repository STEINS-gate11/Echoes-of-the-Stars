============================================================
Bug 01 · 数组未初始化导致乱码
============================================================

【发现时间】2026-07-09 · Day 2
【危险等级】⭐⭐⭐（新手必踩坑，不修会一直冒乱码）


============================================================
【一、现象】
============================================================

写完 WASD 移动 @ 的代码，跑起来后：
  - @ 能正常移动
  - 但走过一些位置之后，屏幕上冒出中文"藹"字
  - 走的越多，"藹"越多，画面被搞得乱七八糟

屏幕现象（简化）：
     +---+---+---+---+           @
     | . | * | . | * |           藹
     | * |\_/| * | . |       藹  藹
     +---+---+---+---+     藹    藹
                     \  |  /  藹    藹
                      .-O-.@@@藹   藹


============================================================
【二、定位过程】
============================================================

一开始不知道为什么，怀疑：
  1. 编码问题（UTF-8/GBK 冲突）？—— 但代码里没有中文
  2. @ 打错了？—— 不像，@ 是英文字符
  3. 场景 txt 编码有问题？—— 检查过是纯 ASCII

最后发现规律：
  - "藹" 总是出现在 @ 走过 且 那一格原本是空白 的地方
  - 说明擦除时 printf("%c", bg[py][px]) 出问题了


============================================================
【三、根本原因】
============================================================

★ char bg[20][50] 只是"申请了 1000 字节的空间"，
  没有把内存清零！

★ 每一行 fgets 读多少写多少，剩下的字节保留原来的垃圾数据。

★ 你以为的 bg 数组：
    bg[3]:         +---+---+---+---+                       \0
                                      ↑ 空格填满

★ 实际的 bg 数组：
    bg[3]:         +---+---+---+---+\0??????????????????????
                                      ↑
                                  \0 之后全是垃圾字节（?）
                                  是栈内存里"上次别人用过的数据"

★ 你的 @ 走到 (30, 3)（bg[3] 有效字符只到 col 25）：
    - bg[3][30] = 垃圾字节
    - 擦除时 printf("%c", 垃圾字节)
    - 恰好那个字节可能是中文 GBK 编码的一半
    - Windows 控制台按 GBK 组合两个字节 → 显示"藹"

★ 这就是"数组未初始化"的经典陷阱：
  C 语言不会自动清零数组！
  你申请的内存里 = 上次那块内存剩下的数据


============================================================
【四、解决方式】
============================================================

★ 方式 A · 用 memset 清零（推荐 · 治本）

  #include <string.h>

  char bg[20][50];
  memset(bg, 0, sizeof(bg));     // 全清零，每个字节都是 \0

  for (int y = 0; y < 20; y++) {
      fgets(bg[y], 50, fp);
      // ...
  }

  之后擦除时 printf("%c", bg[py][px])：
    - 场景内的位置 = 原字符（+ - | 等）✓
    - 场景外的位置 = '\0' = 空字符 = 打不出东西 ✓


★ 方式 B · 定义时初始化（等效方式）

  char bg[20][50] = {0};         // 定义时用 = {0} 清零

  ★ 这是 C 语言的语法糖，等价于 memset


★ 方式 C · 擦除时判断 strlen（治标）

  #include <string.h>

  if (px < (int)strlen(bg[py])) {
      printf("%c", bg[py][px]);
  } else {
      printf(" ");                // 越出真实场景 → 打空格
  }

  ★ 缺点：每次擦除都判断，代码啰嗦


============================================================
【五、教训】
============================================================

★ 铁律 1：C 语言的数组必须自己初始化

  int arr[100];                          // 里面全是垃圾
  int arr[100] = {0};                    // 全 0
  memset(arr, 0, sizeof(arr));           // 全 0

  char str[50];                          // 里面全是垃圾
  char str[50] = {0};                    // 全 0（第一个字节 \0，其余也是 0）
  memset(str, 0, sizeof(str));           // 全 0

★ 铁律 2：跟其他语言不一样，C 不会自动清零

  Java / Python：数组自动初始化为 0 或 null
  C 语言：数组的内容 = 内存里上次剩下的数据（垃圾）

★ 铁律 3：数组下标一定要控边界

  if (px < 0 || px >= 50 || py < 0 || py >= 20) return;
  这样才不会读到数组外的内存


============================================================
【六、修改前后代码对比】
============================================================

【错误的（乱码）】：
  char bg[20][50];
  for (int y = 0; y < 20; y++) {
      fgets(bg[y], 50, fp);
      // ...
  }
  // 之后 printf("%c", bg[py][px]) 可能打出垃圾

【正确的（修复）】：
  char bg[20][50];
  memset(bg, 0, sizeof(bg));      // ← 关键这一行
  for (int y = 0; y < 20; y++) {
      fgets(bg[y], 50, fp);
      // ...
  }
  // 之后 printf("%c", bg[py][px]) 100% 安全
