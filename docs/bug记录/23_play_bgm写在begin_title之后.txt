============================================================
Bug 23 · play_bgm 写在 begin_title 之后 · 标题界面全程没音乐
============================================================

【时间】2026-08-02
【严重程度】中 · 功能缺失，不报错
【位置】main 函数开头

============================================================
【现象】
============================================================

  main 里原本是这样：

    begin_title();
    play_bgm("bgm/title.wav");
    show_the_big_zhi();

  运行后标题界面完全没有音乐。
  按空格进入大字过场，音乐才开始响。

============================================================
【根本原因】
============================================================

  begin_title() 内部是一个死循环：

    void begin_title() {
        ...
        while (1) {
            // 画星空、画流星
            for (int i = 0; i < 10; i++) {
                if (_kbhit()) {
                    char c = _getch();
                    if (c == ' ') return;      // ← 只有这里才出去
                    if (c == 'q') { exit(0); }
                }
                Sleep(50);
            }
        }
    }

  这个函数只有玩家按空格才 return。

  所以：
    begin_title();              ← 卡在这里，玩家在标题界面待多久就卡多久
    play_bgm("bgm/title.wav");  ← 按了空格才执行到

  标题界面本身是没有音乐的。

============================================================
【修复】
============================================================

  调换顺序：

    play_bgm("bgm/title.wav");
    begin_title();
    show_the_big_zhi();

  先起音乐，再进标题界面的循环。

  ★ show_the_big_zhi() 不需要单独加音乐 ——
    大字过场紧接在标题界面之后，
    让它继续放标题曲，情绪是连着的。
    如果那里换歌，玩家刚按空格就听到音乐断一下。

============================================================
【为什么会写错】
============================================================

  写调用点的时候我是按"代码顺序 = 播放顺序"想的：

    begin_title()        标题界面
    play_bgm(title)      标题音乐
    show_the_big_zhi()   大字过场

  看起来很顺 —— 但忽略了 begin_title() 是阻塞的。

  ★ 凡是内部有 while(1) + return 的函数，
    它后面的代码要等用户操作才执行。

  项目里这类阻塞函数有：
    begin_title()          按空格才 return
    show_the_big_zhi()     按空格才 return
    play_pangpai()         按空格才 return
    play_the_pangbai()     每页按 Enter，播完才 return
    playconversation()     每句按任意键
    begin_conver_history() 按 Q 才 return
    play_jiejju_conver()   按空格才 return
    play_A_tiantai_dubai() 按空格才 return
    houji_wait()           按空格才 return

  ★ 要在这些函数"期间"做的事，必须写在它们【之前】。

============================================================
【同类陷阱：get_to_the_hall 里的顺序】
============================================================

  这一处的顺序是对的，但值得对照看：

    void get_to_the_hall(...) {
        system("cls");
        if (pangbai_alredy[0] == 0) {
            play_bgm("bgm/titile-hall.wav");    // ① 先起序幕曲
        }
        play_the_pangbai(0);                     // ② 阻塞：24 页独白
        play_bgm(bgm_chapter[0]);                // ③ 独白完了换大厅曲
        ...
    }

  ① 在 ② 之前 → 序幕曲在独白期间一直放
  ③ 在 ② 之后 → 独白结束才换歌

  ★ 这里"写在之前"和"写在之后"都用到了，
    而且用得都对 —— 因为需求是"独白期间放 A，独白后放 B"。

  对比 bug 本身：
    需求是"标题界面期间放 title" → 必须写在 begin_title() 之前
    写在之后就变成了"标题界面结束后放 title"

============================================================
【教训】
============================================================

  1. 调用点的位置取决于"要在什么期间生效"
     不是按"代码读起来顺不顺"排的

  2. 阻塞函数是一道墙
     它后面的代码要等用户操作
     想在它"期间"生效的东西，全部写在它前面

  3. 这类 bug 编译器完全不管
     没有语法错，没有逻辑错，只是效果不对
     只能靠实际运行发现

  4. 项目里的阻塞函数要列个清单
     这个项目有九个，每次加"期间要生效"的功能都要查一遍
