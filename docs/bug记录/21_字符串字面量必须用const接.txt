============================================================
Bug 21 · 字符串字面量必须用 const char* 接
============================================================

【时间】2026-08-02
【严重程度】中 · 编译不过（C++），C 里只是隐患
【位置】bgm_chapter 数组声明 / play_bgm 参数

============================================================
【现象】
============================================================

  写音乐系统的时候，数组声明忘了写 const：

    char* bgm_chapter[7] = {
        "bgm/hall.wav",
        "bgm/ch0.wav",
        ...
    };

  MSVC 报：

    error C2440: "初始化": 无法从 "const char [14]" 转换为 "char *"

  意思是右边是 const，左边不是，编译器不能帮你把 const 丢掉。

============================================================
【根本原因】
============================================================

  "bgm/hall.wav" 这种直接写在代码里的字符串叫【字符串字面量】。

  它在 C++ 里的类型是：
      const char[14]        ← 注意有 const

  编译器把它放进程序的【只读数据段】（.rdata）。
  程序运行时操作系统把那块内存标记成只读，写进去就崩。

  所以 C++ 规定：
    字符串字面量的类型带 const
    不允许赋值给不带 const 的指针

============================================================
【C 和 C++ 的区别】
============================================================

  C 语言：
    字符串字面量的类型是 char[14]（不带 const）

    char* p = "hello";    // C 里合法，但很危险
    *p = 'H';             // 编译过，运行时崩溃

    C 允许写这种代码，但真去改就崩 —— 内存是只读的。
    这是 C 的一个历史设计缺陷。

  C++：
    把它修正了，字面量类型改成 const char[14]
    从编译期就拦住

  ★ 源.cpp 是 .cpp 后缀，走 C++ 规则，所以报错。
    如果改名成 .c，同样的代码可能只给 warning。

============================================================
【const 到底在保护什么】
============================================================

    const char* p = "hello";

  读作："p 指向的东西是常量。"

    p = "world";      // ✅ 可以，改的是指针指向哪
    *p = 'H';         // ❌ 不行，改的是指针指向的内容
    p[0] = 'H';       // ❌ 同上

  ★ const 保护的是【内容】，不是指针本身。

  如果想连指针也不能改：

    const char* const p = "hello";
    //          ↑     ↑
    //     内容不能改  指针不能改

  数组名本身就不能重新赋值，所以数组不需要第二个 const。

============================================================
【三种写法的区别】
============================================================

    const char* a = "hello";     // 指向只读段  ← 需要的
    char* b = "hello";           // ❌ C++ 编译错
    char c[] = "hello";          // ✅ 复制到栈上，可以改

  第三种是"复制一份到可写内存"：

    char c[] = "hello";
    c[0] = 'H';          // ✅ 合法，c 是栈上数组，可写
    printf("%s\n", c);   // 输出 Hello

  代价是每次都要复制。
  对数组来说也没法这么写：
    char arr[7][20]        占 140 字节且长度固定
    const char* arr[7]     只存 7 个指针，字符串在只读段共享

============================================================
【为什么函数参数也要 const】
============================================================

    void play_bgm(const char* file) {

  两个原因：

  ① 接得住字面量

     play_bgm("bgm/title.wav");     // 传的是 const char*
     play_bgm(bgm_chapter[3]);      // 数组元素也是 const char*

     如果参数写成 char* file，这两个调用都编译错。

  ② 告诉调用者"我不会改你的字符串"

     这是一份契约。看到 const char* 就知道这个函数只读。

============================================================
【最容易混的地方：数组 vs 指针】
============================================================

    char cur_bgm[120] = "";        // 不带 const ✓
    const char* file;              // 带 const   ✓

  为什么 cur_bgm 不用 const？

    因为 cur_bgm 是【数组】，不是指针。
    char cur_bgm[120] = "" 的意思是：
      在内存里开 120 字节的可写空间，把空字符串复制进去

    这块空间是程序自己的（全局数据段的可写部分），随便改。
    strcpy(cur_bgm, file) 就是在改它。

    而 const char* file 是【指针】，指向别处的只读内存。

  对比：

    char arr[120] = "hello";     // 120 字节可写空间，内容是 hello 的副本
    const char* ptr = "hello";   // 4 或 8 字节的指针，指向只读段的 hello

    arr 能改，ptr 指向的内容不能改。

============================================================
【项目里所有该带 const 的地方】
============================================================

  已经带了的（写对了的）：

    const char* the_chapter_Walls[7] = { "=DFT", "=", ... };

    struct doors {
        int x, y;
        const char* text;          // 场景文件名
    };

    struct mujian_zhuanhuan {
        const wchar_t* label;      // 宽字符版同理
        const wchar_t* name;
        const wchar_t* pangbai1;
        const wchar_t* pangbai2;
    };

    struct item_with_conversation {
        const wchar_t* name;
        const wchar_t* item_line[5];
    };

    const wchar_t* mujian_secene[20] = { ... };
    const wchar_t* mujian_sanwen[7][25][9] = { ... };

    void delay_with_Chinese(const wchar_t* text, int times)
    void printemoji(const wchar_t* text)
    void play_jiejju_conver(const wchar_t* text, ...)
    void play_A_tiantai_dubai(const wchar_t* text, ...)

  这次新加的：

    const char* bgm_chapter[7] = { ... };
    void play_bgm(const char* file)

  ★ 规律：
    凡是接【字面量】的指针，都要 const
    L"中文" 的类型是 const wchar_t[N]，同样要 const

============================================================
【教训】
============================================================

  1. 字面量是 const，接它的指针也必须是 const
     这在 C++ 里是硬规则，不是风格建议

  2. 数组不需要 const，指针需要
     char arr[N] = "..."   是复制到可写空间
     const char* p = "..." 是指向只读空间

  3. 函数参数写 const 是双赢
     既能接字面量，又向调用者承诺"我只读"

  4. .cpp 比 .c 严格
     同样的代码在 .c 里可能只 warning
     C++ 从编译期就拦住，这是好事

  5. 报错信息直接告诉你答案
     "无法从 const char [14] 转换为 char *"
     左边缺 const —— 加上就完了
