============================================================
【决定性线索：C2365 重定义】
============================================================

  ★ 函数体里调用函数，永远不会报"重定义"。

  只有编译器认为你在函数外面写代码，才会把
      setColor(15);
  理解成"重新声明一个叫 setColor 的东西"。

  所以看到 C2365 "某个已存在的函数: 重定义"，
  立刻可以断定：上游某个函数头坏了，编译器已经不知道自己在函数里。

============================================================
【崩塌链条】
============================================================

  某个函数头坏了（缺 ) 、缺 { 、L 和引号之间多空格等）
    ↓
  编译器认不出这是函数定义
    ↓
  函数体里的局部变量全变"未声明"
    → C2065  len1 / len2 / i / temp1 / temp2
    ↓
  后面的语句被当成全局声明
    → C4430  缺少类型说明符 - 假定为 int
    ↓
  setColor(15); 被当成重新声明
    → C2365  重定义
    ↓
  大括号配对全乱
    → C2059  语法错误 "}"  "if"
    → C2447  缺少函数标题
    ↓
  一路崩到下一个函数
    → C3861  找不到 clear_new_right

  37 条错误 = 1 个真 bug + 36 条下游噪音

============================================================
【下游错误码清单】
============================================================

  这几个错误码几乎总是连锁反应的下游，不要单独去查：

    C2065  未声明的标识符      → 上游函数头坏了
    C2365  重定义              → 编译器以为你在函数外
    C4430  缺少类型说明符      → 同上
    C2447  缺少函数标题        → 大括号配对乱了
    C3861  找不到标识符        → 崩塌已经蔓延到下一个函数
    C2059  语法错误 "}" / "if" → 解析器彻底迷路

  真正要修的通常是最上面那条 C2143 / C2146（缺分号）
  或者更上面某个看起来"没报错"的函数头。

============================================================
【正确的读法】
============================================================

  1. 把错误列表按行号排序，取行号最小的那一条

  2. 打开那一行，往上看 1~3 行
     真正的错误往往在报错行的上一行
     （编译器是读到下一行才发现上一行有问题）

  3. 修掉它，重新编译

  4. 剩下的通常一起消失

  ★ 不要按错误列表的顺序一条一条修。
     VS 的错误列表默认不按行号排，第一条不一定是最上面那个。

============================================================
【怎么在 VS 里拿到行号】
============================================================

  方法 1 · 输出窗口（最可靠）
    视图 → 输出，或 Ctrl+Alt+O
    下拉框选"生成"
    格式：源.cpp(995): error C2078: ...
    括号里的数字就是行号

  方法 2 · 错误列表双击
    视图 → 错误列表（Ctrl+\, E）
    双击那条错误，光标跳到出错行

  方法 3 · 错误列表加"行"列
    如果错误列表没显示行号
    在列标题上右键 → 勾选"行"

  ★ 如果输出窗口是空的，说明 VS 没真的重编译。
    用"生成 → 重新生成解决方案"强制全编译。

============================================================
【教训】
============================================================

  1. MSVC 报 N 条错误 ≠ 有 N 个 bug
     语法错误会引发雪崩，一个错能报几十条

  2. C2365 "重定义" 是最有价值的线索
     它明确告诉你"编译器认为你在函数外面"
     顺着这条往上找函数头

  3. 修最上面那一条，然后立刻重新编译
     不要连着修五个再编译 —— 你不知道哪个修对了

  4. 报错行号往上看 1~3 行
     缺分号的错误报在下一行

  5. 拿不到行号就没法定位
     不要靠猜。行号是最基本的信息，
     一定要从输出窗口把它找出来
