============================================================
Bug 05 · loadScene 里的 memset 与 sizeof 陷阱
============================================================

【发现时间】2026-07-23
【危险等级】⭐⭐⭐（隐蔽，容易以为已经修过就大意）


============================================================
【一、现象】
============================================================

把加载场景的代码抽成 loadScene 函数后，
运行时又出现了乱码。

具体表现：
  - 场景边角出现"藹""烫""囤"之类乱码字符；
  - A / B / C 位置识别错乱；
  - 或者切换场景后旧场景字符残留。

诡异的是：
  ★ Bug 01 明明已经修过 memset，为什么又来了？


============================================================
【二、定位过程】
============================================================

  1. 检查代码，发现 loadScene 里没写 memset —— 加上；
  2. 加了 memset(bg, 0, sizeof(bg)); 之后还是有乱码；
  3. 打印 sizeof(bg) → 输出 4 或 8，不是 1000；
  4. 明白了：数组作为参数传入函数后 sizeof 失效。


============================================================
【三、根本原因】
============================================================

★ 根本问题不是"忘了 memset"，
  而是"loadScene 里的 sizeof(bg) 根本不是 1000"。

在 main 里：

  char bg[20][50];
  sizeof(bg)   →  1000   （20 × 50 × 1）

在 loadScene 里：

  void loadScene(..., char bg[20][50], ...) {
      sizeof(bg)   →  4 或 8   （指针大小）
  }

原因：

  ★ C 语言规定：数组作为函数参数传递时，
    会"退化"成指向数组首元素的指针。

  ★ 参数 char bg[20][50] 实际等价于 char (*bg)[50]，
    也就是"一个指向长度为 50 的 char 数组的指针"。

  ★ sizeof 作用于指针时，得到的是指针本身的大小，
    在 32 位系统上是 4 字节，64 位系统上是 8 字节。

于是：

  memset(bg, 0, sizeof(bg));
  等价于
  memset(bg, 0, 8);              ← 只清零了 8 个字节！

后面 fgets 只覆盖真正读到的字节，
剩下 1000 - 覆盖字节数 - 8 那部分依然是随机垃圾。


============================================================
【四、为什么在 main 里没问题】
============================================================

在 main 里：

  char bg[20][50];

bg 是"真正的数组"，编译器知道它是 20×50 = 1000 字节。
sizeof(bg) → 1000，正确。

一旦通过参数传递给 loadScene，编译器就不再知道
数组的完整尺寸了，只知道它是"一个指针"。

★ 这是 C 语言最经典的"数组退化为指针"陷阱。


============================================================
【五、解决方式】
============================================================

★ 方式 A · 写死大小（推荐）

  memset(bg, 0, sizeof(char) * 20 * 50);

  或简写为：

  memset(bg, 0, 20 * 50);        // sizeof(char) 恒为 1，可省

  含义：清零 20 × 50 个 char 那么多字节 = 1000 字节。


★ 方式 B · 把行列数当参数传进来

  void loadScene(..., char bg[20][50], int rows, int cols) {
      memset(bg, 0, rows * cols);
      ...
  }

  调用：
    loadScene(..., bg, 20, 50);

  优点：如果以后地图变大，参数改一下就行。
  缺点：多两个参数。


★ 方式 C · 在 main 里就 memset，函数里不再管

  int main() {
      char bg[20][50];
      memset(bg, 0, sizeof(bg));   // main 里 sizeof 是正确的
      loadScene(...);
  }

  ★ 只在初次加载时安全，
    如果切换场景要重新 loadScene，还得再 memset 一次。


★ 方式 D · 定义时初始化（最简洁）

  char bg[20][50] = {0};

  从声明的那一刻起就全 0。
  只覆盖第一次加载；切场景时还得手动 memset。


推荐：loadScene 内部写死 memset(bg, 0, 20 * 50);
     每次调用都自动清零，最省心。


============================================================
【六、修改前后代码对比】
============================================================

【错误版本】：

  void loadScene(const char* filename, char bg[20][50], ...) {
      memset(bg, 0, sizeof(bg));      // ← sizeof(bg) = 8，只清了 8 字节
      FILE* fp = fopen(filename, "r");
      for (int y = 0; y < 20; y++) fgets(...);
      ...
  }

【正确版本】：

  void loadScene(const char* filename, char bg[20][50], ...) {
      memset(bg, 0, sizeof(char) * 20 * 50);   // ← 写死大小
      FILE* fp = fopen(filename, "r");
      for (int y = 0; y < 20; y++) fgets(...);
      ...
  }


============================================================
【七、为什么必加 memset】
============================================================

回顾 Bug 01：

  ★ C 语言局部变量默认不清零；
  ★ 内存里是"上次谁用过留下的"垃圾字节；
  ★ fgets 只覆盖读到的部分，行末的字节不管；
  ★ 未清零区域可能刚好是 GBK 中文编码的一半；
  ★ 屏幕就冒出"藹烫囤"之类的乱码。

memset(bg, 0, 20*50) 把整块内存彻底填 0：

  ★ '\0' 就是空字符，打出来什么也没有；
  ★ 找 A/B/C 的循环碰到 \0 判 != 'A'，不会误判；
  ★ printf("%s", bg[i]) 遇 \0 停止，不会画到垃圾字节。


============================================================
【八、教训】
============================================================

★ 铁律 1：只要数组作为参数传进函数，就别用 sizeof。

  函数外部：sizeof(bg)  正确（数组本身）
  函数内部：sizeof(bg)  错误（指针大小）

  函数内部要清零，写死大小：
    memset(bg, 0, 20 * 50);
  或用参数传行列数进去。

★ 铁律 2：每次调用 loadScene 都会自动清零 —— 这样切场景才安全。

  否则从 prologue 切到 library 时，
  library.txt 短于 prologue.txt 的部分会保留 prologue 的字符。

★ 铁律 3：C 语言的"数组退化为指针"是所有指针陷阱里最基础的一个。

  以后凡是"函数里 sizeof 一个参数数组"，都要意识到危险。
  必要时把数组大小当参数传进去。


============================================================
【九、一句话总结】
============================================================

  Bug 01：忘写 memset → 乱码。
  Bug 05：写了 memset(bg, 0, sizeof(bg))，但 sizeof(bg) 在函数里退化成 8。

  修法：写死 memset(bg, 0, sizeof(char) * 20 * 50);
       每次 loadScene 都会正确清零 1000 字节，
       乱码 & 场景残留全部消失。
