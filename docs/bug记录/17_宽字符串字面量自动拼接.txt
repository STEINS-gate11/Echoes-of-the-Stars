============================================================
Bug 17 · 相邻宽字符串字面量自动拼接 · 第五章旁白丢了一句
============================================================

【时间】2026-07-31
【严重程度】中 · 编译能过,但显示少一行
【位置】源.cpp chapter_zhuanhuan[6] 初始化

============================================================
【现象】
============================================================

  结构体定义:

    struct mujian_zhuanhuan {
        const wchar_t* label;
        const wchar_t* name;
        const wchar_t* pangbai1;
        const wchar_t* pangbai2;
    };

  前 4 章都是对的:

    { L"第 一 章", L"初    遇",
      L"你不记得她是谁了。",                        ← 有逗号
      L"但你还记得,你答应过她要去看星星。" },

  第五章漏了逗号:

    { L"第 五 章", L"回    响",
      L"你终于回来了，"                            ← 漏逗号!
      L"你终于准备好了。",
    },

============================================================
【为什么编译能过】
============================================================

  C/C++ 语言规则:相邻的字符串字面量会自动拼接

    L"abc" L"def"    等价于    L"abcdef"

  这个特性本来是为了写长字符串方便:

    const wchar_t* s = L"这是一个很长的句子,"
                       L"分成两行写更清楚,"
                       L"编译器会自动拼起来。";

  但如果本来想写两个独立的字符串,漏了逗号
  编译器不会报错,它会认为你在故意拼接

============================================================
【实际效果】
============================================================

  写的:
    L"你终于回来了，"
    L"你终于准备好了。",

  编译器看到的:
    L"你终于回来了，你终于准备好了。",

  所以初始化变成:
    label    = L"第 五 章"
    name     = L"回    响"
    pangbai1 = L"你终于回来了，你终于准备好了。"    ← 两句合成一句
    pangbai2 = NULL                              ← 没赋值,默认 NULL

  运行时 play_pangpai 的行为:

    if (temp->pangbai1 != NULL) {
        gotoxy(12, 13);
        delay_with_Chinese(temp->pangbai1, 40);   ← 打一长句
    }
    if (temp->pangbai2 != NULL) {                ← NULL,跳过
        gotoxy(12, 14);
        delay_with_Chinese(temp->pangbai2, 40);
    }

  屏幕上:
    第 13 行:你终于回来了，你终于准备好了。
    第 14 行:(空的)

  其他 4 章:
    第 13 行:第一句
    第 14 行:第二句

  第五章比别的章少一行 —— 视觉不统一

============================================================
【怎么发现的】
============================================================

  肉眼扫代码的时候看到第五章的花括号结构和前面 4 章不一样:

    前 4 章:
      { L"...", L"...",
        L"...",
        L"..." },

    第五章:
      { L"...", L"...",
        L"..."
        L"...",
      },

  两个地方不同:
    1. 中间没逗号
    2. 最后一行有逗号 + 换行才 }

  第 2 点不影响(C++ 允许尾随逗号)
  第 1 点是 bug

============================================================
【修复】
============================================================

  方案 A · 加逗号(保留两句)

    { L"第 五 章", L"回    响",
      L"你终于回来了，",
      L"你终于准备好了。" },

  方案 B · 只留一句(pangbai2 明确 NULL)

    { L"第 五 章", L"回    响",
      L"你终于回来了，你终于准备好了。",
      NULL },

  推荐方案 A —— 和前 4 章格式一致

  另外注意:第五章用的是全角逗号「，」
  前 4 章用的是半角逗号「,」
  这个也该统一(不影响功能,但显示宽度不同)

============================================================
【教训】
============================================================

  1. 字符串数组/结构体初始化,逗号必须逐个数
     C++ 的自动拼接特性让漏逗号变成"静默错误"
     编译器帮不了你

  2. 相同结构的初始化列表要对齐看
     4 个章节格式一样,第 5 个不一样 → 立刻可疑
     格式统一本身就是一种检查手段

  3. 结构体字段没显式赋值 → 静态初始化为 0/NULL
     所以 pangbai2 == NULL 不会崩,只是不显示
     这让 bug 更难发现(不崩不报错,只是少一行)

  4. 全角半角标点混用
     「，」是 U+FF0C,占 2 列
     「,」是 U+002C,占 1 列
     混用会让居中和换行计算出偏差
