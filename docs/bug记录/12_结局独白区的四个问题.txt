============================================================
Bug 12 · 结局独白区的四个问题
============================================================

【时间】2026-07-30
【发生阶段】把独白移到屏幕右侧 + 写 print_with_wrap 自动换行
【严重程度】功能问题 + 闪烁

============================================================
【现象 1 · 屏幕规格搞错了】
============================================================

  错误假设:
    · 一直以为屏幕是 50×25(25 行高)

  实际情况:
    · mode con 显示 30 行 120 列
    · 屏幕宽 120 列,30 行

  影响:
    · y 最大可到 29,不是 24
    · x 最大可到 119,不是 49
    · 之前所有 25 行的设计文档都错了

  验证方法:
    · cmd 里输入 mode con
    · 看"行"和"列"的数字

  解决:
    · main 开头加 system("mode con cols=120 lines=30") 锁死

============================================================
【现象 2 · 独白溢出右边界】
============================================================

  问题:
    · 一行独白最长 34 个中文字 = 68 列
    · 起点 x=55 · 终点 x=123 · 超过 120 列
    · 文字被截断或溢到屏幕外

  解决:
    · 写 print_with_wrap 函数
    · 装不下就自动换行到下一行
    · max_cols=60(留 3 列边距)
    · cur_cols += col_w · col_w = 1(ASCII)或 2(中文/全角)

============================================================
【现象 3 · 标点处换行错误(降智 bug)】
============================================================

  错误代码:
    if (is_punct && cur_chars >= 20) {
        cur_y++;
        cur_x = start_x;
        ...
    }
    /* 标点画在原行末尾 */
    WriteConsoleW(h, &text[i], 1, &written, NULL);

  问题:
    · 标点判断在前,画字符在后
    · 标点确实画了,但 next_is_punct 的逻辑搞错
    · 标点单独留在新行开头(被推下去)

  解决(最终版):
    · 完全去掉"标点智能换行"的逻辑
    · 只用"装不下就强制换行"——最简单、最稳
    · 句号和前面的字永远在同一行
    · 换行点可能在奇怪的字后,但不破坏语义

  教训:
    · 复杂的换行逻辑容易出错
    · "强制换行"已经够用,别自作聪明

============================================================
【现象 4 · clear 范围错(闪屏 bug)】
============================================================

  错误代码:
    for (int yy = 0; yy <= 27; yy++) clear_right(yy);
    /* 每句话前清整个独白区 · 28 行 */

  问题:
    · system("cls") 似的效果:整个右侧独白区全清
    · 上一句话的字被擦掉
    · 闪屏

  解决:
    · 改成只清 2 行:y 和 y+1
    · 短句只占 1 行,长句换行占 2 行
    · 上一句的 y 不同,不会被擦

  for (int yy = y; yy <= y + 3; yy++) clear_right(yy);
  → 改成:
  clear_right(y);
  clear_right(y + 1);

  教训:
    · 清屏范围要刚好,不贪多
    · "为了保险清整个区"反而会擦掉不该擦的东西

============================================================
【附 · print_with_wrap 完整正确版】
============================================================

  void print_with_wrap(const wchar_t* text, int start_x, int start_y, int max_cols, int type_speed) {
      int cur_x = start_x;
      int cur_y = start_y;
      int cur_cols = 0;

      setColor(15);
      gotoxy(cur_x, cur_y);

      for (int i = 0; text[i] != L'\0'; i++) {
          int col_w;
          if (text[i] < 0x80) col_w = 1;
          else col_w = 2;

          if (cur_cols + col_w > max_cols) {
              cur_y++;
              cur_x = start_x;
              cur_cols = 0;
              gotoxy(cur_x, cur_y);
          }

          HANDLE h = GetStdHandle(STD_OUTPUT_HANDLE);
          DWORD written;
          WriteConsoleW(h, &text[i], 1, &written, NULL);
          Sleep(type_speed);

          cur_x += col_w;
          cur_cols += col_w;
      }
  }

  核心就一个判断:装不下就换。
  没有标点判断,没有字符数判断,没有特殊处理。
  简单 = 不容易错。

============================================================
【教训总结】
============================================================

  1. 屏幕规格一定要先验证(mode con),别拍脑袋
  2. 复杂逻辑容易出错,简单逻辑够用就别贪多
  3. 清屏范围要精准,清多了一定出问题
  4. 自动换行的"优雅标点换行"看上去好,实际很难做对
  5. 调试时要分清楚"我以为的"和"实际看到的"
     —— 我看代码以为没问题,实际跑出来有尾巴
     —— 截图为证,别只看代码
