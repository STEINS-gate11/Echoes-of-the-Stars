============================================================
Bug 03 · 打字期间按键残留导致对话自动关闭
============================================================

【发现时间】2026-07-21
【危险等级】⭐⭐⭐（不会编译报错，但严重影响对话体验）


============================================================
【一、现象】
============================================================

给物品 A 加入打字机效果后，正常流程应该是：

  1. 中文逐字出现；
  2. 播放完后出现“按任意键继续……”；
  3. 玩家重新按一个键；
  4. 对话关闭。

实际测试时发现：

  - 打字机播放过程中，如果玩家提前按键；
  - 文字播放完之后，对话会直接关闭；
  - 玩家没有在“按任意键继续”出现后重新按键。

这会让玩家误以为游戏支持跳过，或认为对话系统发生了故障。


============================================================
【二、根本原因】
============================================================

_getch() 会从控制台输入缓冲区读取一个按键。

当打字机正在运行时：

  WriteConsoleW 输出字符
  Sleep 暂停
  WriteConsoleW 输出下一个字符
  ...

这段时间程序没有调用 _getch()，但玩家仍然可以按键。

这些按键不会消失，而是被 Windows 暂时保存在：

  控制台输入缓冲区

当文字播放结束后，程序执行：

  _getch();

_getch() 会立刻取出缓冲区里之前残留的按键，因此不会真正等待一个新按键。

运行时间线：

  文字播放中
      ↓
  玩家提前按空格
      ↓
  空格进入输入缓冲区
      ↓
  文字播放完成
      ↓
  程序执行 _getch()
      ↓
  _getch() 立即读走之前的空格
      ↓
  对话直接关闭


============================================================
【三、解决方式】
============================================================

在正式等待玩家继续之前，先把输入缓冲区里积累的旧按键全部读掉。

添加函数：

void clearInputBuffer() {
    while (_kbhit()) {
        _getch();
    }
}

使用：

  delay_with_Chinese(L"按任意键继续……", 50);

  clearInputBuffer();
  _getch();

含义：

  clearInputBuffer()  清掉打字期间积累的按键
  _getch()            等待玩家重新按下一个新按键


============================================================
【四、clearInputBuffer 逐行解释】
============================================================

void clearInputBuffer() {

定义一个无返回值、无参数的函数。


while (_kbhit()) {

_kbhit() 检查控制台输入缓冲区里是否存在按键：

  返回 0      没有按键
  返回非 0   有按键

只要还有残留按键，循环就继续。


_getch();

从缓冲区取出一个按键，但不保存它。

也就是说：

  读掉并丢弃一个旧按键。

如果缓冲区里有 3 个按键，循环会执行 3 次，把它们全部读走。


============================================================
【五、为什么不能只写一个 _getch】
============================================================

错误方案：

  _getch();   // 只读掉一个旧按键
  _getch();   // 等待继续

如果玩家在播放期间按了多个键，第一个 _getch 只清掉一个，第二个仍可能读到另一个旧按键。

正确方案：

  while (_kbhit()) {
      _getch();
  }

循环清理，直到缓冲区彻底为空。


============================================================
【六、正确的对话等待模板】
============================================================

gotoxy(0, 23);
setColor(8);
delay_with_Chinese(L"按任意键继续……", 50);

// 清除打字过程中提前按下的所有旧按键
clearInputBuffer();

// 现在才真正等待玩家的新按键
_getch();


============================================================
【七、设计意义】
============================================================

项目已经确定：

  不做打字机快进。

因此对话输入必须满足：

  - 打字期间按键无效；
  - 必须完整播放文字；
  - 播放完成后，玩家重新按键才能关闭对话。

clearInputBuffer 正是用来保证这条游戏规则。


============================================================
【八、教训】
============================================================

★ 键盘输入不是“按过就消失”，而是可能先进入缓冲区等待程序读取。

★ 一个程序即使没有编译错误、没有崩溃，也可能有“交互时序 Bug”。

★ 涉及动画 + 按键等待时，要考虑：

  1. 动画期间玩家能否按键；
  2. 按键是否进入缓冲区；
  3. 动画结束后是否会误读旧输入；
  4. 是否需要主动清空缓冲区。

★ 当前固定模板：

  先播放文字
  → 清空输入缓冲区
  → 等待新按键
  → 关闭对话
