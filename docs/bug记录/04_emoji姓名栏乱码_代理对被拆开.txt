============================================================
Bug 04 · Emoji 姓名栏乱码：代理对被打字机拆开
============================================================

【发现时间】2026-07-22
【危险等级】⭐⭐（不会崩溃，但视觉效果异常）


============================================================
【一、现象】
============================================================

给 B 和 C 加打字机对话之后，姓名栏使用：

  delay_with_Chinese(L"📖 空白日记本", 80);
  delay_with_Chinese(L"🖼 模糊照片", 80);

运行时发现：

  ⭐ 折纸星星  →  显示正常
  📖 空白日记本 →  emoji 变成方框或乱码
  🖼 模糊照片   →  emoji 变成方框或乱码

同一份代码，一部分 emoji 正常，一部分乱码。


============================================================
【二、根本原因】
============================================================

Windows 使用 UTF-16 编码。

在 UTF-16 里：

  基本平面字符（U+0000 到 U+FFFF）  → 1 个 wchar_t
  补充平面字符（U+10000 到 U+10FFFF）→ 2 个 wchar_t（代理对）

举例：

  「星」        1 个 wchar_t
  ⭐ U+2B50     1 个 wchar_t
  📖 U+1F4D6    2 个 wchar_t
  🖼 U+1F5BC    2 个 wchar_t

delay_with_Chinese 的实现：

  for 每个 wchar_t：
      一次输出 1 个 wchar_t
      Sleep

对于代理对：

  第 1 轮  输出高代理 wchar_t（半个 emoji）
  第 2 轮  输出低代理 wchar_t（另半个 emoji）

Windows 拿到"半个 emoji"没办法正确渲染，
只能显示为方框、问号或乱码。


============================================================
【三、为什么 ⭐ 又是正常的】
============================================================

⭐ 是基本平面字符：

  1 个 wchar_t，本身就是一个完整字符。

所以 delay_with_Chinese 每次输出 1 个 wchar_t 时，
⭐ 一次就能正确显示。


============================================================
【四、解决方式】
============================================================

写一个"整段一次性输出"的函数：

void printWideAll(const wchar_t* text) {
    HANDLE output = GetStdHandle(STD_OUTPUT_HANDLE);
    DWORD written;

    int len = 0;
    while (text[len] != L'\0') {
        len++;
    }

    WriteConsoleW(output, text, len, &written, NULL);
}

一次把整段宽字符串交给 WriteConsoleW，
Windows 内部会自动识别代理对，正确渲染。

使用：

  gotoxy(2, 22);
  setColor(14);
  printWideAll(L"📖 空白日记本");


============================================================
【五、函数分工】
============================================================

  delay_with_Chinese
    - 一次输出 1 个 wchar_t
    - 用于对话正文，逐字动画
    - 只用于不含 emoji 的中文文本

  printWideAll
    - 一次输出整段字符串
    - 用于姓名栏、结局标题等含 emoji 的文本
    - 没有逐字动画


============================================================
【六、修改前后对比】
============================================================

修改前（乱码）：

  gotoxy(2, 22);
  setColor(14);
  delay_with_Chinese(L"📖 空白日记本", 80);

修改后（正常）：

  gotoxy(2, 22);
  setColor(14);
  printWideAll(L"📖 空白日记本");


============================================================
【七、教训】
============================================================

★ 不要以为一个字符在源代码里"看起来是一个字"就一定占 1 个 wchar_t。

★ Emoji 在 UTF-16 里可能是 1 个或 2 个 wchar_t，
  不能一律按"一个字一个 wchar_t"处理。

★ 分辨方式（够用即可）：
  - 手机 emoji 键盘挑到的图标 → 大概率是代理对
  - 基础符号 ★ ✦ ○ ⭐ → 大概率单个 wchar_t

★ 在打字机中出现 emoji 时，改用 printWideAll，不要试图逐个 wchar_t 输出。

★ 如果一定要逐字动画又要 emoji：
  必须扩展打字机，判断高代理范围。
  当前项目不做，用分工方案代替。


============================================================
【八、控制台字体的次要问题】
============================================================

即使 wchar_t 正确、WriteConsoleW 调用正确，
仍然可能显示成方框。这时问题不在代码，而在字体：

  - 老 cmd + Consolas 字体：可能不完整支持 emoji
  - Windows Terminal + 默认字体：一般支持
  - Windows 7：普遍不支持

如果代码逻辑已经确认正确，emoji 仍然是方框，
先尝试：

  - 换成 Windows Terminal
  - 属性 → 字体 换成 Cascadia Mono 或微软雅黑
  - 或者临时改用 [星] [书] [照] 这种纯字符替代
