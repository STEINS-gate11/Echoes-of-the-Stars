============================================================
《星空回响》Bug 记录 09 · 流星覆盖静态字符
============================================================

【现象】
主界面 begin_title 的流星飞过之后，屏幕上一些字消失了。
比如天琴座的一颗 . 没了，或者说明文字里少了一个字。

【定位过程】
流星飞的时候：
  1. 画 ✦ 到新位置
  2. 用空格擦掉上一步的 ✦

问题在于——上一步的位置上，其实原本有其它字符（比如天琴座的点、
说明文字里的字）。流星画 ✦ 覆盖了它，擦除时又把整格擦成空格，
原来的字符就永远消失了。

【根本原因】
"擦除 + 重画" 是流星动画的通用模式。
但流星只知道自己上一帧在哪，不知道那一格原本有什么。
所以擦除后无法恢复。

这是一个"层混淆"的 bug：
  - 静态层（一次性画的天琴座、文字）画在同一层
  - 动画层（流星）画在同一层
  - 动画擦除时无法区分是自己画的还是静态层画的

【解决方式】
方案 1（本项目采用）：改流星路径，避开静态字符区
  把边界从 (x>5, y<19) 改成 (x>40, y<9)
  → 流星只在右上角划一小段
  → 不再经过说明文字、寄语等区域
  → 但也不再经过天琴座（除了 x=66 附近，通过验证不冲突）

方案 2：维护静态字符表 + 擦除时查表恢复
  struct static_char { int x, y; wchar_t* ch; int color; };
  static_char static_layer[N] = { ... };
  擦除时先查表，如果这格原本有静态字符，恢复它
  代码多，但通用性强

方案 3：流星飞完后重画整个静态层
  流星飞完那一刻，重画所有静态元素
  只是流星飞行过程中屏幕仍然会"缺一块"

方案 4：每帧重画整个界面
  最粗暴，但可能闪烁

【教训】
1. "擦除 + 重画" 只对"永远只有自己一层"的动画有效
   如果画面上有其它同层的字符，会互相干扰

2. 设计动画路径时，要意识到会不会经过其它已有元素

3. 更严谨的做法是分层：
   静态层  = 只画一次，不动
   动态层  = 每帧重画
   动画擦除时应该"擦回底层"而不是"擦成空格"

4. 本项目为了简单，只用改路径避开的办法
