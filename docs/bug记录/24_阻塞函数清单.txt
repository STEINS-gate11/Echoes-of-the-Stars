【为什么要这份清单】
============================================================

  bug 23 的错误是这样犯的：

    begin_title();                    ← 里面是 while(1)，按空格才 return
    play_bgm("bgm/title.wav");        ← 所以这行等标题界面结束才执行

  写的时候按"代码顺序 = 播放顺序"想的：
    begin_title()        标题界面
    play_bgm(title)      标题音乐
    show_the_big_zhi()   大字过场

  看起来很顺 —— 但忽略了 begin_title() 是阻塞的。

  ★ 凡是内部有 while + _getch() 的函数，
    它后面的代码要等用户操作才执行。

  ★ 要在这些函数"期间"生效的东西，必须写在它们【之前】。

  这类 bug 编译器完全不管：没有语法错，没有逻辑错，只是效果不对。
  只能靠实际运行发现，或者靠这份清单预防。

【两种阻塞的区别】
============================================================

  【A · while + _getch() —— 完全阻塞】

    while (_getch() != ' ') {
    }

    _getch() 会一直等，等到用户按键才返回。
    循环体在按键前【一次都不执行】。

    ★ 这意味着：不能在这种循环里做"定时检查"。
      比如"每 50 毫秒查一次音乐停了没" —— 做不到。

    这就是为什么 MCI 放 mp3 的循环方案在这个项目里行不通
    （见 bug 22 末尾）。

  【B · while (!_kbhit()) + _getch() —— 可轮询】

    while (!_kbhit()) {
        Sleep(50);
        int temp = now_time();      // ← 这里可以做定时检查
        if (temp == -1) { ... }
        if (temp == 1) { draw_memory_secene(); }
    }
    char c = _getch();

    _kbhit() 只查"有没有按键"，不等待，立刻返回。
    所以循环体每 50 毫秒执行一次，可以做别的事。

    ★ main 的主循环用的是这种，所以记忆值倒计时能跑。
      其他 15 处用的是 A 种，所以里面做不了定时检查。

  ★ 一个特例 —— begin_title 和 show_the_big_zhi 用了混合写法：

      for (int i = 0; i < 10; i++) {
          if (_kbhit()) {
              char c = _getch();
              if (c == ' ') return;
          }
          Sleep(50);
      }

    外层 while(1) 画动画，内层 for 用 _kbhit() 轮询 10 次（500 毫秒）。
    这样既能放动画又能响应按键。

【正确的写法 · 三种情况】
============================================================

  【情况 1 · 要在阻塞期间生效 → 写在前面】

    play_bgm("bgm/title.wav");     ← 标题界面期间要放
    begin_title();

  【情况 2 · 要在阻塞结束后生效 → 写在后面】

    play_the_pangbai(0);            ← 24 页独白
    play_bgm(bgm_chapter[0]);       ← 独白完了才换大厅曲

  【情况 3 · 前后都要 → 前后都写】

    void get_to_the_hall(...) {
        system("cls");
        if (pangbai_alredy[0] == 0) {
            play_bgm("bgm/titile-hall.wav");    // ① 独白期间放序幕曲
        }
        play_the_pangbai(0);                     // ② 阻塞：24 页
        play_bgm(bgm_chapter[0]);                // ③ 独白完换大厅曲
        ...
    }

    ★ 这一处的顺序是对的，而且同时用到了"前"和"后" ——
      因为需求就是"独白期间放 A，独白后放 B"。

【教训】
============================================================

  1. 调用点的位置取决于"要在什么期间生效"
     不是按"代码读起来顺不顺"排的

  2. 阻塞函数是一道墙
     它后面的代码要等用户操作
     想在它"期间"生效的东西，全部写在它前面

  3. 加任何"期间要生效"的功能前，先查这份清单
     音乐是第一个，以后可能还有：
       - 背景动画（比如独白期间星空一直闪）
       - 计时器（比如某个场景限时）
       - 自动存档提示

  4. while + _getch() 里做不了定时检查
     要定时检查必须改成 while (!_kbhit()) + Sleep 轮询
     这是选 PlaySound 而不是 MCI 的一个隐含原因

  5. 这类 bug 编译器完全不管
     没有语法错、没有逻辑错，只是效果不对
     只能靠运行发现，或靠清单预防
