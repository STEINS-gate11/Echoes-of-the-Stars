一、为什么要两套打字机
============================================================

  三个结局的独白量不一样,场景需求也不一样:

  【C 结局 · 星尘归海】
    - 场景:书房 + 镜子
    - 独白:静态,不需要动画
    - 用 play_jiejju_conver

  【B 结局 · 未完待续】
    - 场景:书房
    - 独白:静态,不需要动画
    - 用 play_jiejju_conver

  【A 结局 · 星光彼岸】
    - 场景:书房 → 街道 → 楼梯 → 天台
    - 天台段需要星空闪烁 + 流星
    - 用 play_A_tiantai_dubai(等待时跑动画)

  两套函数的差别只有一处:while (_getch() != ' ') 里做什么

============================================================
二、play_jiejju_conver(B/C 用)
============================================================

  void play_jiejju_conver(const wchar_t* text, int y, int delay1, int delay2) {
      for (int i = y; i < y + 8; i++) {
          clear_new_right(i);          // 清 8 行独白区
      }
      gotoxy(55, y);
      setColor(15);
      delay_with_huanhang(text, 55, y, 60, delay1);   // 自动换行打字
      Sleep(delay2);                   // 读完停顿
      gotoxy(76, 29);
      setColor(8);
      printemoji(L"[ 按 空 格 继 续 ]");
      clearbutter();
      while (_getch() != ' ') {
                                       // 空的 —— 只是等
      }
      clear(24);
  }

  参数含义:
    text   —— 要打的字
    y      —— 独白起始行(B/C 都传 11)
    delay1 —— 每个字的间隔(28 毫秒)
    delay2 —— 打完后停顿(100~450 毫秒,按情绪调)

  delay2 的用法(A/B/C 都一样的规律):
    100 ms —— 短句,一句话就完("你回到桌前。")
    150 ms —— 一般叙述
    200 ms —— 需要一点停顿
    250 ms —— 情绪重的段落
    350 ms —— 转折句("——它也是藏青色的。")
    400 ms —— 重击("「——那是骗你的。」")
    500 ms —— 最重的("「我爱你。」")

三、play_A_tiantai_dubai(A 用)
============================================================

  void play_A_tiantai_dubai(const wchar_t* text, int delay1, int delay2) {
      for (int i = 11; i <= 18; i++) {
          clear_new_right(i);          // 固定清 11~18 行
      }
      gotoxy(55, 11);                  // 固定从 11 行开始
      setColor(15);
      delay_with_huanhang(text, 55, 11, 60, delay1);
      Sleep(delay2);
      gotoxy(76, 29);
      setColor(8);
      printemoji(L"[ 按 空 格 继 续 ]");
      clearbutter();
      while (_getch() != ' ') {
          draw_tiantai();              // ← 关键差别:等待时画星空
          Sleep(50);
      }
      clear(29);
  }

  和 B/C 版的三个差别:

  1. 没有 y 参数 —— A 结局独白位置固定在 11 行
     因为 A 只有一个独白区,不需要灵活调

  2. while 里跑 draw_tiantai()
     玩家不按空格 → 星空一直闪 + 流星一直飞
     按了空格 → 立刻进下一段

  3. clear(29) 而不是 clear(24)
     因为 A 的提示在第 29 行(B/C 也是 29,但 B/C 清的是 24)
     这是个不一致的地方,后来改成都用 29 更好

============================================================
四、delay_with_huanhang · 自动换行的核心
============================================================

  void delay_with_huanhang(const wchar_t* text, int x, int y, int max_cols, int delay) {
      int cur_x = x;
      int cur_y = y;
      int cur_cols = 0;
      setColor(15);
      gotoxy(cur_x, cur_y);
      for (int i = 0; text[i] != L'\0'; i++) {
          int temp = 0;
          if (text[i] < 0x80) temp = 1;    // ASCII 占 1 列
          else temp = 2;                   // 中文占 2 列

          if (cur_cols + temp > max_cols) {   // 装不下就换行
              cur_x = x;
              cur_y++;
              cur_cols = 0;
              gotoxy(cur_x, cur_y);
          }

          gotoxy(cur_x, cur_y);
          HANDLE temp2 = GetStdHandle(STD_OUTPUT_HANDLE);
          DWORD written;
          WriteConsoleW(temp2, &text[i], 1, &written, NULL);
          Sleep(delay);
          cur_x = cur_x + temp;
          cur_cols = cur_cols + temp;
      }
  }

  三个关键点:

  1. 列宽判断(见笔记 26)
     text[i] < 0x80 → 1 列
     否则 → 2 列
     不能用字符数算,必须用列数

  2. 换行条件只有一个
     if (cur_cols + temp > max_cols)
     "装不下就换" —— 不管标点,不管断词

     早期版本试过标点换行(逗号句号不留在行首)
     结果标点被推到下一行单独一个字,更丑
     最后砍掉所有标点逻辑,只保留最简单的规则

  3. cur_x 和 cur_cols 是两个变量
     cur_x    是屏幕绝对坐标(55, 57, 59...)
     cur_cols 是本行已用列数(0, 2, 4...)
     不能合并 —— 因为 x 起点不是 0

============================================================
五、clear_new_right · 只清右半屏
============================================================

  void clear_new_right(int line) {
      gotoxy(52, line);
      for (int i = 52; i < 119; i++) {
          printf(" ");
      }
  }

  为什么从 52 开始:
    结局场景画在左半屏(x 0~49)
    独白区在右半屏(x 55~115)
    清屏只能清右边,否则场景会被擦掉

  为什么到 119:
    实测控制台是 120 列宽(不是 80)
    留 1 列余量防止自动换行

  和 clear(line) 的差别:
    clear(line)          —— 从 x=0 清到 x=78,整行
    clear_new_right(line) —— 从 x=52 清到 x=118,只右半

============================================================
六、独白区的行数计算
============================================================

  B/C:for (int i = y; i < y + 8; i++)   → 清 8 行(11~18)
  A  :for (int i = 11; i <= 18; i++)    → 清 8 行(11~18)

  为什么是 8 行:
    独白区宽 60 列
    一段最长的独白大约 350 个中文字
    350 × 2 / 60 ≈ 12 行

  实际测下来最长的段落到不了 8 行
  留 8 行有余量,又不会碰到第 19 行以下的场景元素

  提示行在 29 行:
    gotoxy(76, 29);
    这是屏幕最后一行(实际 30 行 = 0~29)
    独白 11~18 + 提示 29 → 中间 19~28 空着不用

七、教训
============================================================

  1. 一个函数只做一件事
     两套打字机差别只有 while 里那两行
     但硬要合并成一个函数(加个 flag 参数)会更难读
     宁可写两遍

  2. delay2 是情绪控制器
     不是随便填的数
     100 → 500 是一条情绪曲线
     写完 A 结局 130 段之后回头看
     delay2 的分布本身就是一份情绪谱

  3. 屏幕尺寸必须实测
     早期以为 80×25,按这个算居中全偏
     实测 120×30 才对
     用 test_y_range 打印一堆数字看到哪一行截断
