【一、项目全景架构】
============================================================

《星空回响》是一个控制台交互叙事游戏，架构分四层：

  ┌──────────────────────────────────────────────┐
  │  第 4 层：main 主循环（游戏引擎）              │
  │  - 读按键、调度、渲染                          │
  ├──────────────────────────────────────────────┤
  │  第 3 层：场景函数 + 对话函数（游戏逻辑）      │
  │  - get_to_the_hall / get_to_the_secene         │
  │  - playconversation                            │
  │  - begin_conver_history                        │
  ├──────────────────────────────────────────────┤
  │  第 2 层：数据结构（数据层）                   │
  │  - itemDialogs 静态数据表                      │
  │  - chapterWalls / chapterColors 配置表         │
  │  - conver_node 动态链表                        │
  ├──────────────────────────────────────────────┤
  │  第 1 层：基础工具（渲染层）                   │
  │  - gotoxy / setColor / printemoji /            │
  │  - load_secene / draw_dialog                   │
  └──────────────────────────────────────────────┘


============================================================
【二、显示层 vs 数据层】
============================================================

游戏里所有可见的东西，都有两份记录：

  显示层：屏幕上你看到的字符
  数据层：内存里 bg[20][50] 数组存的字符

  ★ 铁律：两层必须同步

  比如玩家拾了 A：
    - 显示层：屏幕上 A 变成空格
    - 数据层：bg[ay][ax] = ' '
    → 玩家再走过来，擦除逻辑查 bg 得到空格，不会打出 A 残影

  比如场景里的墙 =：
    - 显示层：屏幕上有 =（被 load_secene 画出来）
    - 数据层：bg[i][j] = '='
    → checkwall(bg[py-1][px]) 查 bg 判断能不能走

  哪一层没同步，就出 bug（见 bug 记录 06）


============================================================
【三、全局数据一览】
============================================================

▌ 状态变量

  int cur_chapter = 0;
      当前章号：0=hall, 1~6=章节
      被 checkwall / getcolor 用来查规则

  char bg[20][50];
      场景数据层，存当前场景每格是什么字符
      载入 .txt 时填，拾取物品时改

  int flagA, flagB, flagC;
      当前场景 3 件物品的拾取状态
      A、B: 0 未拾, 1 已拾
      C:    0 未看, 1 察觉暗星, 2 看清, 3 已拾


▌ 配置数据（编译时确定，运行时不改）

  doors difsecene[6]
      6 个门的坐标 + 对应场景 .txt 文件名

  int game_begin_locked[7]
      章节解锁状态，初始 {0,1,0,0,0,0,0}
      只有章 1 一开始解锁；每进一章解锁下一章

  const char* the_chapter_Walls[7]
      每章的墙字符集合
      hall: "=D"     普通章: "="     rooftop: "=[]#"
      planetarium: "" (无墙)

  every_secene_color chaptercolors[7][12]
      每章每个字符对应的颜色
      比如章 1 的 '+' 是深黄 6，章 3 的 '=' 是深灰 8

  item_with_conversation item_everyconversition[6][3]
      15 件物品的名字 + 5 行对话
      本项目的核心叙事数据


▌ 动态数据（运行时增长）

  conver_node* head, * tail
  int total_size
      双向链表，存玩家拾取过的物品对话历史
      每拾取一件就 malloc 一个节点接到 tail


============================================================
【四、所有函数职责一览】
============================================================

▌ 第 1 层：基础工具

  gotoxy(x, y)          光标定位到 (x, y)
  hideCursor()          隐藏控制台光标
  setColor(c)           设置字符颜色
  clear(line)           清一行
  clearbutter()         清空键盘缓冲区
  cleararray(x, y)      清多行
  delay_with_Chinese    打字机效果（一个字一个字打）
  printemoji            整个字符串一次性输出（emoji 用）
  draw_dialog(x,y,l,w)  画对话框（上下横线）
  isreact(x,y,px,py)    判断玩家和目标是否相邻

▌ 第 2 层：数据查询

  get_senece_color(ch, chapter)
      查某章某字符的颜色
      找不到默认白 15

  checkwall(c)
      判断字符 c 是不是当前章的墙
      A/B/C 通用挡；其他查 the_chapter_Walls

  have_already_pick(chapter, slot)
      查某章某件物品是否已拾取
      遍历链表找匹配的节点

▌ 第 3 层：场景管理

  load_secene(文件名, bg, A/B/C坐标)
      从 .txt 读进 bg[][]
      逐字符按章节颜色画到屏幕
      A/B 金黄，C/? 隐藏

  draw_the_beginning_room()
      画 hall 的标题 + 6 个 D 门
      解锁的金黄，未解锁的灰色

  get_to_the_hall(...)
      清屏 + 设 cur_chapter=0 + 重置 flag + 出生 + load hall

  get_to_the_secene(..., chapter)
      清屏 + 设 cur_chapter + 从链表恢复 flag + 出生
      + load 场景 + 解锁下一章 + 抹掉已拾物品

▌ 第 4 层：对话与历史

  playconversation(item, color)
      播一件物品的完整对话（一句一句显示）
      每行遇 NULL 停

  insert_tail(item, chapter)
      新建 conver_node 尾插到链表

  clear_and_see_you()
      程序退出前遍历释放所有 malloc 的节点

  draw_conver_history(p, idx)
      画回看界面一屏：物品名、5 行文本、"X/N 页码"

  begin_conver_history()
      B 键触发的回看主循环
      从 tail 开始，A/D 翻页，Q 退出

▌ 第 5 层：主循环

  main()
      整个游戏的调度中心
      读按键 → 分派到对应逻辑


============================================================
【五、主循环运行流程】
============================================================

每次按键触发一轮：

  1. 画状态栏（拾取计数 X/3 或 hall 说明）
  2. 画底部提示条（WASD/E/B/Q 说明）
  3. 在 (px, py) 画玩家 @
  4. 等按键 _getch()
  5. 擦除老 @ 位置（用当前章色恢复原字符）
  6. 分派按键：
       Q → 回 hall（或退出）
       B → 回看历史
       E → 进门（hall）/ 拾取物品（场景）
       WASD → 尝试移动（checkwall 挡不挡）
  7. 循环

【六、数据流：拾取物品的全过程】
============================================================

  玩家在章 1 走到 A 边上，按 E
    ↓
  main 判断当前不是 hall
    ↓
  取当前章物品数据 items = itemDialogs[cur_chapter-1]
    ↓
  isreact 判定玩家和 A 相邻 & flagA == 0
    ↓
  playconversation(&items[0], 14)
    - 循环 5 次显示 5 行文本
    - 每行等 SPACE
    ↓
  insert_tail(&items[0], cur_chapter)
    - malloc 一个新节点
    - 填名字、5 行、章号
    - prev = tail, next = NULL
    - tail 换成新节点
    - total_size++
    ↓
  bg[ay][ax] = ' '        （数据层抹除）
  gotoxy(ax, ay); printf(" ")  （显示层抹除）
    ↓
  flagA = 1


============================================================
【七、数据流：进出场景的全过程】
============================================================

  玩家在 hall 走到 3 号门，按 E
    ↓
  main 判断当前是 hall
    ↓
  isreact 判定玩家和 D 相邻 & 该章解锁
    ↓
  get_to_the_secene(..., chapter=3)
    - system("cls")
    - cur_chapter = 3               ★ 先设，才能让 load 用对颜色
    - flagA = have_already_pick(3, 0)  查链表恢复
    - flagB = have_already_pick(3, 1)
    - flagC = have_already_pick(3, 2) ? 3 : 0
    - px = 24, py = 18              重置出生点
    - strcpy(cursecene, "rooftop.txt")
    - load_secene(...)              画场景
    - game_begin_locked[4] = 1      解锁下一章
    - 已拾物品的 A/B/C 逐一抹掉

  玩家在场景按 Q
    ↓
  get_to_the_hall(...)
    - cls
    - cur_chapter = 0
    - flagA/B/C = 0
    - px = 24, py = 11
    - load hall.txt
    - draw_the_beginning_room 画标题 + 6 个 D


============================================================
【八、关键设计思想】
============================================================

★ 数据驱动（Data-Driven）

  加新章、改颜色、改墙、改文案，都只改数据表，不改代码逻辑。

    加新章：itemDialogs 加一层 + chapterColors 加一层
            + chapterWalls 加一行 + difsecene 加一门
    改颜色：改 chapterColors[X][i].color 的数字
    改文案：改 itemDialogs[X][Y].item_line[Z] 的字面量

  好处：数据和代码分离，答辩讲"我的项目可扩展性强"。


★ 单一数据源（Single Source of Truth）

  拾取状态只有链表记录，flag 是"每次进场景从链表推算"。

  错误做法：flag 独立记录 + 链表也记录 → 两处可能不一致
  正确做法：链表是唯一权威，flag 每次从链表读

  好处：不会出现"链表说拾了，flag 说没拾"的矛盾。


★ 关注点分离（Separation of Concerns）

  各函数职责单一：
    load_secene       只管 .txt 加载 + 画背景，不管游戏状态
    checkwall         只管判断墙，不管画面
    playconversation  只管播对话，不管入链表
    insert_tail       只管入链表，不管显示

  好处：函数复用，改一处不影响其他。


★ 显示层与数据层同步

  凡是屏幕上的字符，bg[][] 里必须有对应记录。
  否则被覆盖后无法恢复。

【九、答辩总结（一句话讲完项目）】
============================================================

"这是一个 C 语言写的控制台交互叙事游戏，
   6 章 15 件物品，双向链表存对话历史，
   数据驱动的墙表和颜色表，
   单一数据源保证拾取状态跨场景一致。"

  技术亮点：
    · 双向链表 + malloc / free 内存管理
    · 数据驱动配置（数组化的墙/颜色/对话表）
    · 全局状态机（cur_chapter 决定所有查表）
    · 显示/数据分离，逐字符渲染 + 章节颜色查表
    · 关注点分离的分层设计
