【二、动画分三种时序模式】
============================================================

▌ 静态一次性
    只画一次，不管
    例：天文书标题、寄语、天琴座

▌ 顺序动画
    setColor / gotoxy / printemoji / Sleep 顺序执行
    有开始有结束，玩家不能中断
    例：大字浮现、四角亮起、结尾流星

▌ 循环动画
    while (1) 里循环重画，直到玩家按键退出
    必须配 _kbhit() 保证响应
    例：星带呼吸、内星闪烁、主界面流星、引导条呼吸

★ 关键理解:
    静态元素只画一次
    循环动画每帧重画
    两者叠在同一画面上


============================================================
【三、多层并行动画的底层原理】
============================================================

▌ 关键变量：xunhuannumber（帧计数器）
    每循环一次 +1
    是所有动画的"共同时钟"
    每个动画元素查这个时钟得到自己的进度

▌ 5 帧呼吸的原理
    color_total[5] = { 8, 7, 6, 7, 8 }
    setColor(color_total[xunhuannumber % 5])
    → 每帧换一档颜色，5 帧一循环
    → 视觉上就是"呼吸"

▌ 错相位的原理
    (xunhuannumber + phase) % 5
    每颗星有自己的 phase 偏移量
    同一时刻，不同 phase 的星处在呼吸的不同阶段
    → 6 颗星"各闪各的"，不齐刷刷

▌ 状态机（流星）
    3 个变量：
      · liu_xing_tai       正在飞 / 未飞
      · liu_xing_count      飞到第几步
      · liu_xing_jishi      未飞时的倒计时

    每帧执行流程：
      if 未飞 → 倒计时 -1，归零就切"正在飞"
      if 正在飞 → 算新位置 → 擦上一步 → 画新一步 → step++
                 出边界就擦最后一颗、切回"未飞"

▌ 环形字符串（滚动字幕）
    rolling_text 是一整段固定文字
    每帧从 (rolling_offset + i) % rolling_len 位置开始，
    拷 80 字符到屏幕上
    rolling_offset 每帧 +1
    → 走到末尾自动折回开头，形成无缝循环
    → 视觉上就是从右往左滚动


============================================================
【四、"擦除 + 重画" 是所有动画的通用模式】
============================================================

▌ 任何位置会变的元素都遵循：
    1. 计算这一帧的新位置 / 新颜色
    2. 在旧位置打空格（如果宽字符打两个空格）
    3. 在新位置画字符

▌ 只变颜色不变位置的（星带、内星）
    不用擦除
    因为字符位置一样，直接用新颜色重画就覆盖了

▌ 位置会变的（流星、滚动字幕）
    必须显式擦除
    否则前一帧的画面残留，变成静止的轨迹

▌ 特殊情况：滚动字幕自动覆盖
    因为每帧都打整整 80 字符，等于把上一帧全遮住了
    不用显式擦


============================================================
【五、_kbhit vs _getch · 边动画边等按键】
============================================================

▌ _getch 阻塞：等玩家按键
    用在主循环、对话、章节过场结束

▌ _kbhit 非阻塞：看有没有键
    用在边动画边等按键（主界面呼吸、大字过场结束）

▌ 拆分 Sleep 提高响应速度
    不写 Sleep(500)
    写 for (i=0; i<10; i++) { _kbhit 查一下, Sleep(50) }
    动画时长不变，但按键响应从 500ms 提到最长 50ms

▌ 详见 学习笔记 20


============================================================
【六、clearbutter 的作用与位置】
============================================================

▌ 什么时候需要 clearbutter
    ★ 规则：等玩家按键的循环之前，
      如果前面有等待时间（动画/Sleep/打字机），
      一定要 clearbutter

    ★ 否则玩家在等待期间按的键会堆积在缓冲区
      循环一开始就被立刻取走响应，玩家看不到画面

▌ 具体位置
    begin_title 无等待，进入 while 前可选加
    show_the_big_zhi 有 8~10 秒动画，必须加

▌ 每帧都清是错的
    clearbutter 应该在 while(1) 之前
    不是 while 循环里每一帧都清
    否则玩家在 500ms 内按的键会被下次清掉


============================================================
【七、结构体命名的差异】
============================================================

▌ 匿名结构体
    struct { int x, y, phase; } inner_stars[6] = { ... };
    只能用一次，不能复用

▌ 命名结构体
    struct inner_star { int x, y, phase; };
    inner_star inner_stars[6] = { ... };
    可复用，代码清晰
    ★ 项目里其它结构体都是命名的，风格一致

【八、动画元素的位置冲突问题】
============================================================

▌ 问题
    流星飞过时，覆盖了下面的静态字符
    擦除后那格变成空格
    静态字符（天琴座、寄语文字）永远消失

▌ 修法 1：改路径避开
    缩小流星飞行范围
    只让流星在没有字符的区域划过
    例：右上角只到 (40, 8) 就停

▌ 修法 2：擦除后重画
    维护一张"静态字符表"
    擦除后查表恢复
    通用但代码多

▌ 修法 3：飞完重画整个静态层
    流星飞完那一刻，重画所有静态元素

▌ 修法 4：每帧重画整个界面
    最粗暴，但可能闪烁

★ 本项目选修法 1（改路径）
    因为最简单，且流星在天琴座附近划一小段视觉效果就够

【九、寄语随机 · 用 time(NULL) 而非 rand】
============================================================

▌ time(NULL) 返回从 1970 到现在的秒数
    是不断变化的大整数
    每次运行时间不同，得到不同值

▌ ((int)time(NULL)) % 5
    把大整数折叠成 0~4，用作数组下标
    ★ 不需要 srand + rand，一行搞定

▌ 缺点
    同一秒内重启游戏两次，会看到同一句
    但这不是问题


============================================================
【十、随机化间隔 · 减少规律感】
============================================================

▌ 流星"下次多久再来"
    liu_xing_jishi = 8 + (xunhuannumber % 8)

    → 每次的间隔在 8 到 15 帧之间
    → 玩家不会觉得"每 20 秒来一颗"的呆板感

▌ 用主循环的帧计数器作随机源
    因为 xunhuannumber 本身就是不断变化的
    不用 rand，也不用 time
    ★ 帧数变化就是"内建的随机数"

【十一、简化天琴座 · 用位置暗示星座】
============================================================

▌ 天琴座 α 是织女星，但没人一眼认得出"这几个点是天琴座"

▌ 我的做法
    5 个字符散布在右上角 (64~70, 4~8)
    中央用 ✦ 突出显示（就是织女）
    其它 4 颗用 . 淡化
    → 有心的玩家能看出星座轮廓
    → 无心的玩家也不觉得突兀
    ★ "半强化"的装饰手法


============================================================
【十二、5 帧调色板 · 平滑呼吸】
============================================================

▌ color_total[5] = { 8, 7, 6, 7, 8 }
    灰 → 浅金 → 深黄 → 浅金 → 灰
    首尾两端相同（8）
    保证循环时不会突然"跳"

▌ 呼吸周期 = 5 × 500ms = 2.5 秒
    足够慢，不会让人心烦
    足够快，一分钟内玩家能感知到

▌ 只有 3 种颜色（8, 7, 6）
    2 亮 2 暗 1 中间
    比"忽亮忽暗"（只 2 帧）更自然
    比"更细分 10 帧"更省事


============================================================
【十三、6 颗内星 phase 覆盖 0~4】
============================================================

▌ phase = { 0, 2, 1, 3, 4, 2 }
    覆盖 0~4 全部 5 个阶段
    重复用 2（选最亮的深黄），画面更醒目

▌ 效果
    同一时刻 6 颗星有多种颜色
    避免"齐刷刷一起闪"的呆板

▌ 通用规律
    n 颗物体做同类动画
    phase 从 0 到 (5-1) 中挑，尽量分布均匀
    如果 n > 5，就必然有重复

【十四、答辩问答】
============================================================

Q1: 主界面为什么用 _kbhit 而不是 _getch？
    _getch 阻塞会卡死呼吸动画。
    _kbhit 非阻塞，边呼吸边查键。

Q2: 6 颗内星用错相位是什么意思？
    每颗星有自己的 phase 偏移，
    同一时刻处在呼吸的不同阶段。
    避免齐刷刷一起闪。

Q3: 流星怎么飞的？
    位置公式 x=70-step*4, y=3+step
    每帧算新位置 → 擦上一步 → 画新一步 → step++
    出边界就切回"未飞"，倒计时重新开始

Q4: 滚动字幕怎么做的？
    每帧从长字符串里取 80 字符打出去
    (rolling_offset + i) % rolling_len 保证下标合法
    rolling_offset++ 就是滚动

Q5: 为什么每帧要拆 10 段 Sleep 50ms？
    整段 Sleep(500) 会让按键响应最长 500ms
    拆分后最长 50ms，玩家感觉不到延迟
