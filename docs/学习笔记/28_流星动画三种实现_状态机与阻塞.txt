一、项目里一共有三套流星
============================================================

  1. begin_title 里的流星     —— 主界面,局部变量 + 大循环
  2. draw_tiantai 里的流星    —— A 结局天台,static 变量 + 每帧调一次
  3. draw_A_liuxing          —— A 结局收尾,阻塞式一次性播放

  三套的写法完全不同,因为调用方式不同

============================================================
二、第一种 · begin_title(局部变量 + 大循环)
============================================================

  void begin_title() {
      int liu_xing_tai = 0;       // 局部变量
      int liu_xing_count = 0;
      int liu_xing_jishi = 10;
      ...
      while (1) {                 // 整个动画在一个大 while 里
          // 画背景星
          ...
          // 流星逻辑
          if (liu_xing_tai == 0) {
              liu_xing_jishi--;
              if (liu_xing_jishi <= 0) {
                  liu_xing_tai = 1;
                  liu_xing_count = 0;
                  liu_xing_jishi = 10 + (xunhuannumber % 8);
              }
          }
          if (liu_xing_tai) {
              int x = 70 - liu_xing_count * 4;
              int y = 3 + liu_xing_count;
              if (x > 40 && y < 9) {
                  // 擦上一帧
                  if (liu_xing_count > 0) {
                      int px = 70 - (liu_xing_count - 1) * 4;
                      int py = 2 + liu_xing_count;
                      gotoxy(px, py);
                      printemoji(L" ");
                  }
                  gotoxy(x, y);
                  setColor(14);
                  printemoji(L"✦");
                  liu_xing_count++;
              }
              else {
                  // 飞出边界,擦掉最后一帧,重置状态
                  ...
                  liu_xing_tai = 0;
              }
          }
          xunhuannumber++;
          // 检查按键
          for (int i = 0; i < 10; i++) {
              if (_kbhit()) { ... }
              Sleep(50);
          }
      }
  }

  特点:
    - 变量是局部的,因为整个动画生命周期就在这个函数里
    - while(1) 是主循环,每转一圈画一帧
    - 按键检查用 _kbhit() 非阻塞,for 循环里等 500 毫秒

  适用:整个界面就是动画,不需要和外部交互

三、第二种 · draw_tiantai(static 变量 + 每帧调一次)
============================================================

  void draw_tiantai() {
      static int A_xunhuannumber = 0;      // ← static!
      int number = A_xunhuannumber % 5;
      int color_total[5] = { 8, 7, 6, 14, 6 };
      setColor(color_total[number]);
      gotoxy(0, 0);
      printemoji(L"   *    .    '    *    .    '    *    .    '   ");
      gotoxy(0, 1);
      printemoji(L"     .    *    '    .    *    '    .    *      ");
      setColor(color_total[number]);
      gotoxy(47, 0);
      printemoji(L"✦");
      A_xunhuannumber++;

      static int A_liu_xing_tai = 0;       // ← 三个都 static
      static int A_liu_xing_count = 0;
      static int A_liu_xing_jishi = 10;
      if (A_liu_xing_tai == 0) {
          A_liu_xing_jishi--;
          if (A_liu_xing_jishi <= 0) {
              A_liu_xing_count = 0;
              A_liu_xing_tai = 1;
              A_liu_xing_jishi = 10 + (A_xunhuannumber % 8);
          }
      }
      if (A_liu_xing_tai) {
          int x = 100 - A_liu_xing_count * 7;
          int y = 3 + A_liu_xing_count;
          if (x > 40 && y < 11) {
              ...擦上一帧,画这一帧...
              A_liu_xing_count++;
          }
          else {
              ...擦掉,重置...
              A_liu_xing_tai = 0;
          }
      }
  }

  为什么必须用 static:

    这个函数是在 play_A_tiantai_dubai 的等待循环里被调的:

      while (_getch() != ' ') {
          draw_tiantai();      // ← 每 50 毫秒调一次
          Sleep(50);
      }

    每次调用都是一次全新的函数进入
    如果变量是局部的 → 每次都重置成 0 → 流星永远停在第一帧

    static 让变量的值在函数返回后保留
    下一次调用时接着上次的值继续

  这是状态机模式:
    函数本身不循环,只负责"画一帧"
    状态存在 static 变量里
    外面的循环负责反复调用

  适用:动画要和其他逻辑(等按键)混在一起跑

============================================================
四、第三种 · draw_A_liuxing(阻塞式一次性)
============================================================

  void draw_A_liuxing() {
      for (int i = 0; i < 6; i++) {
          int x = 90 - i * 10;
          int y = 3 + 2 * i;
          if (i > 0) {
              int px = 90 - (i - 1) * 10;
              int py = 1 + 2 * i;
              gotoxy(px, py);
              printf(" ");
          }
          gotoxy(x, y);
          setColor(14);
          printemoji(L"✦");
          Sleep(400);          // ← 直接 Sleep,阻塞
      }
  }

  特点:
    - 不用 static,因为整个动画在一次调用里跑完
    - Sleep(400) 直接阻塞,不管按键
    - 玩家没法跳过

  为什么这里可以阻塞:
    这是 A 结局最后一个动作
    在 return_to_titile(0) 之前
    玩家已经读完 130 段独白了,这 2.4 秒必须让他看完
    不给跳过是设计意图,不是偷懒

  适用:剧情关键动画,不允许跳过

============================================================
五、擦除上一帧的坐标偏移
============================================================

  三套流星都有这段:

    if (count > 0) {
        int px = 起点 - (count - 1) * 步长;
        int py = 起点y_偏移 + count;      // ← 注意这里
        gotoxy(px, py);
        printf(" ");
    }

  以 draw_tiantai 为例:

    当前帧:  y = 3 + count
    擦除帧:  py = 2 + count

    count=0 时:画 y=3
    count=1 时:画 y=4,擦 py=2+1=3   ← 对,擦掉了上一帧的 3
    count=2 时:画 y=5,擦 py=2+2=4   ← 对,擦掉了上一帧的 4

  规律:擦除的 y 起点比绘制的 y 起点小 1
       因为 count 已经 ++ 过了

  这个 off-by-one 很容易写错
  写错的症状:流星尾巴留一串 ✦ 不消失(见 bug 09)

六、三套流星的参数对比
============================================================

  ┌──────────────┬────────────┬────────────┬────────────┐
  │              │ begin_title│ draw_tiantai│draw_A_liuxing│
  ├──────────────┼────────────┼────────────┼────────────┤
  │ 起点 x       │     70     │    100     │     90     │
  │ x 步长       │     -4     │     -7     │    -10     │
  │ 起点 y       │      3     │      3     │      3     │
  │ y 步长       │     +1     │     +1     │     +2     │
  │ x 下限       │    > 40    │    > 40    │   跑 6 帧  │
  │ y 上限       │    < 9     │    < 11    │   跑 6 帧  │
  │ 帧间隔       │  50 ms     │  50 ms     │  400 ms    │
  │ 变量类型     │   局部     │   static   │   局部     │
  │ 循环归属     │  函数内    │  函数外    │  函数内    │
  │ 能否跳过     │   能       │   能       │   不能     │
  └──────────────┴────────────┴────────────┴────────────┘

  x 步长越大 → 流星越"陡"(横向移动快)
  y 步长越大 → 流星越"斜"(纵向下落快)

  draw_A_liuxing 的 y 步长是 +2,所以它的轨迹最斜
  这是刻意的 —— 最后一颗流星要最醒目

============================================================
七、教训
============================================================

  1. static 是状态机的钥匙
     函数要"记住上次的状态" → static
     函数每次都从头开始 → 局部变量

  2. 擦除必须算上 count++ 的时机
     count++ 放在画完之后 → 擦除用 count-1
     count++ 放在画之前   → 擦除用 count
     搞混就留尾巴

  3. 阻塞 vs 非阻塞是设计选择
     不是"能不能",是"该不该"
     剧情高潮就该阻塞,让玩家看完
     界面装饰就该非阻塞,别挡着操作

  4. 三套代码看起来重复,但不该合并
     参数不同,变量作用域不同,循环归属不同
     强行抽象成一个函数需要 5 个参数 + 1 个模式 flag
     那样更难读
