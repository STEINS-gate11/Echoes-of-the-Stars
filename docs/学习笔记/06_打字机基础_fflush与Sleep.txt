============================================================
【一、打字机效果的基本原理】
============================================================

打字机效果不是一次输出整段文字，而是：

  1. 取出一个字符
  2. 输出这个字符
  3. 立即刷新输出
  4. 暂停一段时间
  5. 取下一个字符
  6. 重复，直到遇到字符串结束符 \0

基础代码：

void typewriter(const char* text, int delayMs) {
    for (int i = 0; text[i] != '\0'; i++) {
        printf("%c", text[i]);
        fflush(stdout);
        Sleep(delayMs);
    }
}

调用示例：

  typewriter("Echoes of the Stars", 80);

意思是：
  将 "Echoes of the Stars" 逐字符输出，
  每个字符之间暂停 80 毫秒。


============================================================
【二、fflush(stdout) 是什么】
============================================================

▌ stdout

stdout 表示程序的"标准输出流"，通常就是控制台窗口。

printf 输出的字符有时不会立刻送到屏幕，而是先放进一个临时区域：

  输出缓冲区

系统可能等缓冲区积累一些内容后，再一次性显示。


▌ fflush(stdout)

fflush(stdout) 的意思：

  把标准输出缓冲区里的内容立即送到控制台显示。

例子：

  printf("A");
  fflush(stdout);

这样可以确保 A 现在就出现在屏幕上。

如果不写 fflush(stdout)：
- 某些环境下字符仍然可能正常逐字出现；
- 也可能攒几个字符后一起显示；
- 打字机效果的表现不够稳定。

因此打字机循环中主动刷新更可靠。

需要头文件：

  #include <stdio.h>


▌ 注意

标准用法：

  fflush(stdout);   // 刷新输出流

不建议依赖：

  fflush(stdin);    // 对输入流的行为不标准，不作为本项目方案


============================================================
【三、Sleep(delayMs) 是什么】
============================================================

Sleep 是 Windows 提供的暂停函数。

需要头文件：

  #include <windows.h>

例子：

  Sleep(1000);

表示当前程序暂停 1000 毫秒，也就是 1 秒。

常见数值：

  Sleep(10)       10 毫秒
  Sleep(40)       40 毫秒
  Sleep(80)       80 毫秒
  Sleep(500)      0.5 秒
  Sleep(1000)     1 秒

注意：
- Sleep 的单位是毫秒，不是秒；
- Sleep 会暂停当前程序的执行；
- 暂停期间，这一段代码不会继续向下运行。


============================================================
【四、delayMs 是什么】
============================================================

delayMs 不是系统自带变量，而是 typewriter 函数的参数：

  void typewriter(const char* text, int delayMs)

名称含义：

  delay = 延迟
  Ms    = milliseconds，毫秒

调用：

  typewriter("ABC", 500);

此时：

  text = "ABC"
  delayMs = 500

所以循环里的：

  Sleep(delayMs);

实际相当于：

  Sleep(500);

也就是每输出一个字符，暂停 0.5 秒。


============================================================
【五、完整运行过程】
============================================================

代码：

  typewriter("ABC", 500);

执行过程：

  第 1 轮：
    text[0] = 'A'
    printf 输出 A
    fflush 立即显示 A
    Sleep 暂停 0.5 秒

  第 2 轮：
    text[1] = 'B'
    printf 输出 B
    fflush 立即显示
    Sleep 暂停 0.5 秒

  第 3 轮：
    text[2] = 'C'
    printf 输出 C
    fflush 立即显示
    Sleep 暂停 0.5 秒

  第 4 次检查：
    text[3] = '\0'
    循环条件失败，结束。

玩家看到：

  A
  等待 0.5 秒
  AB
  等待 0.5 秒
  ABC


============================================================
【六、三个函数分别负责什么】
============================================================

  printf("%c", text[i]);
    → 输出当前字符

  fflush(stdout);
    → 要求当前字符立即显示

  Sleep(delayMs);
    → 显示后暂停一会儿，制造逐字节奏

口诀：

  打印 → 刷新 → 等待 → 下一个字符


============================================================
【七、英文版练习代码】
============================================================

#include <stdio.h>
#include <windows.h>

void typewriter(const char* text, int delayMs) {
    for (int i = 0; text[i] != '\0'; i++) {
        printf("%c", text[i]);
        fflush(stdout);
        Sleep(delayMs);
    }
}

int main() {
    typewriter("Echoes of the Stars", 80);
    return 0;
}


============================================================
【八、为什么当前只测试英文】
============================================================

英文 ASCII 字符通常是 1 字节：

  text[i] 每次正好取出一个完整英文字符。

中文可能使用多字节编码：

  text[i] 每次只取一个字节，可能把一个汉字拆开，导致乱码。

因此当前学习顺序是：

  1. 先用英文理解逐字符循环；
  2. 确认 printf / fflush / Sleep 的工作方式；
  3. 后续再根据项目编码方式实现中文打字机；
  4. 当前不要求学习位运算或 UTF-8 字节判断。


============================================================
【十、为什么会想到设计 typewriter 函数】
============================================================

这个函数不是凭空想到的，也不是必须背下来的固定公式。

它来自对需求的逐步拆解。


▌ 第 1 步：先明确需求

原来的对话是一次全部显示：

  printf("你拿起那颗星星。它很旧了。");

玩家一瞬间就看到整段文字。

但项目想要的效果是：

  你
  你拿
  你拿起
  你拿起那
  ……

也就是文字要逐字出现。


▌ 第 2 步：把“逐字出现”翻译成程序步骤

人的描述：

  文字一个字一个字出现。

程序描述：

  1. 取当前字符；
  2. 输出当前字符；
  3. 暂停一段时间；
  4. 移到下一个字符；
  5. 没到字符串末尾就继续。

一旦写成这五步，就自然得到循环：

  for (int i = 0; text[i] != '\0'; i++) {
      printf("%c", text[i]);
      fflush(stdout);
      Sleep(delayMs);
  }

所以打字机效果的本质不是一个神秘 API，而是：

  字符串遍历 + 单字符输出 + 延时


▌ 第 3 步：为什么要把循环封装成函数

如果只播放一句对话，可以直接写循环：

  const char* text = "Echoes of the Stars";

  for (int i = 0; text[i] != '\0'; i++) {
      printf("%c", text[i]);
      fflush(stdout);
      Sleep(80);
  }

但游戏里有大量对话：

  A 折纸星星
  B 空白日记
  C 模糊照片
  图书馆 3 件物品
  天台 3 件物品
  医院 3 件物品
  Vega 独白
  三个结局
  TE

如果每一句都复制一遍 for 循环：

  - 代码重复；
  - 改速度要改很多地方；
  - 容易漏改；
  - main 会越来越长；
  - 后面难维护。

因此把“重复使用的一整套操作”封装为函数：

  void typewriter(const char* text, int delayMs)

以后只需要调用：

  typewriter("第一句话", 40);
  typewriter("第二句话", 80);
  typewriter("第三句话", 50);


▌ 第 4 步：为什么函数需要两个参数

每次调用，变化的内容有两个：

  1. 要播放的文字不同；
  2. 播放速度可能不同。

因此把它们定义成参数：

  const char* text   要播放的文字
  int delayMs        每个字符之间的毫秒延迟

固定不变的是操作过程：

  遍历 → 输出 → 刷新 → 暂停

这就是函数设计的一般方法：

  把“变化的部分”做成参数，
  把“固定的步骤”写在函数内部。


▌ 第 5 步：为什么中文又要单独一个函数

英文可以逐个 char 输出，因为英文字符通常占一个字节。

中文可能占多个字节，直接逐个 char 输出会拆开汉字。

所以需求进一步变化：

  不仅要逐字输出，
  还要保证中文每次输出一个完整字符。

因此设计中文版本：

  void typewriterChinese(const wchar_t* text, int delayMs)

内部使用：

  WriteConsoleW

而不是普通：

  printf("%c")


============================================================
【十一、从需求想到函数的一般方法】
============================================================

以后遇到新功能，可以按这个顺序思考：

  1. 玩家看到的效果是什么？
  2. 这个效果能拆成哪些小步骤？
  3. 哪些步骤需要循环？
  4. 这套步骤会不会反复使用？
  5. 哪些部分每次会变化？
  6. 固定步骤写进函数，变化部分做成参数。

应用到打字机：

  效果：逐字显示
      ↓
  步骤：取字 → 输出 → 等待 → 下一个字
      ↓
  循环：直到 \0
      ↓
  重复：所有对话都需要
      ↓
  变化：文字内容、播放速度
      ↓
  函数：typewriter(text, delayMs)


============================================================
【十二、对本项目的意义】
============================================================

以后所有文本都可以复用同一个打字机函数：

  主线物品对话
  层间旁白
  章节标题
  A/B/C 结局
  Vega 引入独白
  Vega 触发点
  Vega 结尾字幕
  TE 七幕

如果想统一调整整个游戏的文字速度，只需修改参数或一个默认常量：

  const int TYPEWRITER_MS = 40;

调用：

  typewriterChinese(L"你拿起那颗星星。", TYPEWRITER_MS);


============================================================
【十三、一句话总结】
============================================================

不是先想到函数，再找地方使用。

而是：

  先有“逐字出现”的需求
  → 拆成“输出一个字 + 等待 + 重复”
  → 发现全游戏会反复使用
  → 才封装成 typewriter 函数。

函数的来源：

  重复需求的抽象与封装。
