============================================================
《星空回响》学习笔记 20 · 阻塞按键 vs 非阻塞按键
============================================================

【学习时间】2026-07-29
【场景】主界面星带 5 帧呼吸时，玩家按空格能否立即响应


============================================================
【一、问题】
============================================================

主界面上，屏幕要"一直做动画"（星带颜色循环变化），
同时"随时准备接受玩家按键"。

用之前学的 _getch() 会有问题：

  while (1) {
      改颜色 ...
      Sleep(500);
      char c = _getch();      // ← 卡住等按键
      if (c == ' ') break;
  }

_getch() 是阻塞式的 —— 一直等到玩家按键才继续。
玩家不按 → 画面停在这一帧，颜色不再变 → 呼吸动画死了。

需要一种"看一眼有没有键，没键就走"的函数。


============================================================
【二、_kbhit()】
============================================================

_kbhit() 属于 <conio.h>，作用：
  - 检查按键缓冲区是否有键
  - 有键     → 返回非 0（真）
  - 没键     → 返回 0（假），立刻返回，不等

★ 它不阻塞。只是"问一下当前有没有键"，问完立刻走。


============================================================
【三、正确的组合模式】
============================================================

_kbhit() + _getch() 一定要搭配用：

  if (_kbhit()) {
      char c = _getch();     // ← 这时不会阻塞，因为确定有键
      if (c == ' ') ...
  }

★ 单独用 _kbhit() 不用 _getch()：
    键留在缓冲区，下次查还是有 → 会重复响应

★ 单独用 _getch() 不用 _kbhit()：
    没键时会卡住 → 动画死

★ 两个搭配：
    有键才取，取完就消失，动画不停


============================================================
【四、主界面星带的实现】
============================================================

  for (int i = 0; i < 10; i++) {
      if (_kbhit()) {
          char c = _getch();
          if (c == ' ') return;
          if (c == 'q') { system("cls"); exit(0); }
      }
      Sleep(50);
  }

【它做什么】

"等 500 毫秒，但每 50 毫秒检查一次玩家有没有按键"

【为什么不直接 Sleep(500)】

如果一次睡 500ms：
  玩家按下键 → 要等最长 500ms 才响应 → 手感卡

拆成 10 × 50ms：
  动画时长不变（还是 500ms）
  但每 50ms 查一次按键
  玩家按下键最长 50ms 就有反应 → 人几乎感觉不到延迟


============================================================
【五、两个函数的对比】
============================================================

  函数         行为              适用场景
  ---------    --------------    --------------------------
  _getch()     阻塞，等按键      主循环、对话、章节过场结束
  _kbhit()     非阻塞，看有没     边动画边等按键
                键，立即返回     （主界面呼吸、后台状态显示）


============================================================
【六、类比】
============================================================

  _getch()（阻塞）
    = 打电话给朋友，一直响到接为止
    = 打不通就一直响，你什么都做不了

  _kbhit() + _getch()（非阻塞）
    = 看一眼手机有没有消息
    = 有就回，没有就继续干别的事

  主界面的呼吸动画，就是
    "每 50 毫秒看一眼手机、剩下时间画画"的模式


============================================================
【七、注意事项】
============================================================

_kbhit() 只查缓冲区，不会清空。

如果玩家在动画开始前疯狂按键，那些键都存在缓冲区里，
动画一开始就会立刻响应。

不想响应之前按的键，动画开始前先 clearbutter() 清一下：

  clearbutter();       // 清空之前的按键
  while (1) { ... }    // 动画循环

【九、答辩问答】
============================================================

Q1: _getch() 和 _kbhit() 什么区别？
    _getch 阻塞等按键；_kbhit 非阻塞看有没有键。

Q2: 为什么主界面用 _kbhit 不用 _getch？
    因为主界面星带要一直呼吸，不能等玩家按键才动画。
    _getch 会卡住，_kbhit 不会。

Q3: 为什么不直接 Sleep(500) 一次睡够，睡完再查按键？
    响应延迟会很大（最长 500ms 才响应玩家）。
    拆成 10 × 50ms，响应快，动画顺滑。

Q4: _kbhit 要不要跟 _getch 搭配？
    要。只用 _kbhit 不用 _getch，键留在缓冲区会重复响应；
    只用 _getch 不用 _kbhit，会卡住。

Q5: 什么时候用 _kbhit，什么时候用 _getch？
    需要"边动作边等按键"用 _kbhit（主界面、倒计时）
    只需"等玩家按键"用 _getch（对话推进、章节过场、主循环）
