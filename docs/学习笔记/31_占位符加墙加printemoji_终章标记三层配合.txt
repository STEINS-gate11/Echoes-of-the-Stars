============================================================
一、要解决的问题
============================================================

  6 章全玩完之后，大厅正中要出现：

        ✦
     —— 终章 ——

  玩家走到旁边按 E，进入 A 或 B 结局。

  三个要求：
    1. 没玩完 6 章时，一个字都不显示
    2. 玩家的 @ 不能走到那两行上，把文字擦掉
    3. 玩家走到旁边按 E 要能触发

============================================================
二、为什么不能直接把 ✦ 写进 hall.txt
============================================================

  场景数据是 char 数组：

    char bg[20][50];

  load_secene 用 fgets 读，用 printf("%c") 画。

  char 只能存 ASCII（0~127）。
  ✦ 是 U+2726，中文是 U+4E00~U+9FFF —— 都存不进 char。

  所以 hall.txt 里只能放 ASCII 占位符，
  再用 printemoji 在同一位置盖上真正的字符。

  ★ 这个套路项目里已经有了：
    hall.txt 里的门是 ASCII 的 'D'
    draw_the_beginning_room 再用 printf 上色重画
    终章标记照抄这个思路

============================================================
三、三层配合
============================================================

  【第一层 · hall.txt 放占位符】

    第 14 行（数组 row 13）：
      =                       FF                      =
      （= + 23 空格 + FF + 22 空格 + =）

    第 15 行（数组 row 14）：
      =                TTTTTTTTTTTTTT                 =
      （= + 16 空格 + T×14 + 17 空格 + =）

    FF 在 index 24、25 —— ✦ 的位置（占 2 格，防 ✦ 宽度不确定）
    T×14 在 index 17~30 —— "—— 终章 ——" 的位置

    列宽算法：
      —— 4 列 + 空格 1 + 终章 4 列 + 空格 1 + —— 4 列 = 14 列
      居中 → x 从 (48-14)/2 = 17 开始

    两行都必须是 49 字符，和其他行一致。

  【第二层 · F T 设为墙】

    const char* the_chapter_Walls[7] = {
          "=DFT",     // ← 原来 "=D"，章 0 是 hall
          "=",
          ...
    };

    checkwall(char c) 遍历 the_chapter_Walls[cur_chapter] 找匹配。
    hall 是 cur_chapter = 0 → 查 "=DFT"
    F 和 T 在里面 → 返回 1 → 是墙

    main 里的移动检查：
      else if (c == 'w' && py > 0 && !checkwall(bg[py-1][px]))py--;

    撞墙就不移动 → @ 永远走不到那两行上
    → 文字永远不会被擦掉

    ★ 这是"物理占位"：用碰撞系统保护显示区域，
      而不是每次都重画文字。

  【第三层 · load_secene 过滤，不画出来】

    for (int i = 0; i < 20; i++) {
        for (int j = 0; j < 50; j++) {
            char ch = bg[i][j];
            if (ch == '\0' || ch == ' ' || ch == 'A' || ch == 'B'
                || ch == 'C' || ch == '?'
                || ch == 'F' || ch == 'T') {      // ← 加这个
                continue;
            }
            setColor(get_senece_color(ch, cur_chapter));
            gotoxy(j, i);
            printf("%c", ch);
        }
    }

    continue 跳过 → 不画到屏幕 → 玩家看不见 F 和 T
    但 bg 数组里 F T 还在 → checkwall 照样判墙

    ★ 数据层和显示层分离：
      数据在（碰撞有效），视觉隐藏（不画）
      这和 C / ? 的处理完全一样

  【第四层 · 完成后才画真字符】

    draw_the_beginning_room() 末尾：

      if (all_chapter_done()) {
          setColor(14);
          gotoxy(24, 13);
          printemoji(L"✦");
          setColor(6);
          gotoxy(17, 14);
          printemoji(L"—— 终章 ——");
      }

    没完成 → 不进 if → 一个字符都不画

    ★ 为什么塞在 draw_the_beginning_room 里，
      而不是单独写 draw_finale_marker()：

      draw_the_beginning_room 已经在两个地方被调用：
        get_to_the_hall（每次从章节返回大厅）
        main 的 c == 'b' 分支（从回看返回）

      塞在里面 → 自动更新，不用记得额外调用
      少一个出 bug 的点

============================================================
四、为什么用 pangbai_alredy 判完成
============================================================

  int all_chapter_done() {
      for (int i = 1; i <= 6; i++) {
          if (pangbai_alredy[i] == 0) return 0;
      }
      return 1;
  }

  项目里有两个数组可以用来判进度：

    game_begin_locked[i]  表示"能不能进"
      进过第 5 章就解锁第 6 章
      但解锁 ≠ 玩过 —— 玩家可能解锁了却不进去

    pangbai_alredy[i]     表示"看过开场"
      play_the_pangbai(idx) 播完后置 1
      只有真进去了才置 1

  ★ 判完成必须用 pangbai_alredy。
    用 game_begin_locked 会让玩家跳过最后一章就能进终章。

  索引说明：
    pangbai_alredy[0] 是序幕（hall 的开场），不算章节
    pangbai_alredy[1..6] 是六章
    所以循环从 1 开始

五、触发判定用 isreact
============================================================

  int hall_react(int px, int py) {
      if (!six_chapter_done()) {
          return 0;
      }
      if (isreact(px, py, 24, 13)) {
          return 1;
      }
      if (isreact(px, py, 25, 13)) {
          return 1;
      }
      return 0;
  }

  isreact 是项目里已有的函数：

    int isreact(int x, int y, int px, int py) {
        int dx = abs(x - px);
        int dy = abs(y - py);
        return (dx + dy == 1);
    }

  曼哈顿距离 == 1 → 上下左右相邻（不含对角）

  判两格（24,13）和（25,13）→ 玩家从左、右、上任一侧都能触发

  触发点分布：
            (24,12) (25,12)     ← 上方可触发
    (23,13) [ FF ]   (26,13)    ← 左右可触发
            (24,14) (25,14)     ← T 墙，走不到

  玩家路径：
    起点 (24, 11) → 按 s → (24, 12) → 按 E → 触发
    按 1 次 s + 1 次 E，极容易找

============================================================
六、占位符选择的注意事项
============================================================

  选 F 和 T 之前查了 7 个场景文件（用 grep 确认）：
    prologue / library / rooftop / hospital
    planetarium / finale / hall
  都没有 F 和 T 字符 → 安全

  ★ 为什么要查：
    load_secene 的过滤是全局的，不分章节。
    如果第 3 章的场景文件里有 T（比如画一个 T 形结构），
    那个 T 也会变透明。

  备选字符（也查过，7 个文件都没有）：
    ^  &
  不安全的：
    ~  在章节 1/3/4/6 的 chaptercolors 里已经用了（装饰）

============================================================
七、这个套路可以复用的地方
============================================================

  任何"要在场景里放一个中文/emoji 标记"的需求：

    1. hall.txt 或场景文件里放 ASCII 占位符
    2. the_chapter_Walls 里加进去（如果要防走上去）
    3. load_secene 过滤（如果不想显示占位符）
    4. 在绘制函数里用 printemoji 盖真字符
    5. 用 isreact 判交互

  项目里已经用这个套路的：
    D  门（第 1、4 步）
    A B C  物品（第 2、3 步 + 单独绘制）
    F T  终章标记（全四步）
