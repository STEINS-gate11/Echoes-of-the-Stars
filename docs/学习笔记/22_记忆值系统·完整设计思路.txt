============================================================
【一、系统要解决的问题】
============================================================

游戏的核心叙事是"重新想起她"。
如果玩家可以无限时间地慢慢逛,那"重新想起"就没重量。
需要一个机制让玩家感受到"记忆在流失"。

▌ 需求
    1. 有一个数值代表"记忆",从 100 慢慢降到 0
    2. 玩家看得见(HUD)
    3. 玩家能感受到时间压力
    4. 但不能惩罚"读故事" —— 幕间散文和对话时不扣
    5. 归零 → 触发结局 C(星尘归海 · 遗忘结局)
    6. 走路探索会扣,而且要匀速地扣(每 8 秒 -1)


============================================================
【二、核心设计:钟表逻辑】
============================================================

★ 关键顿悟:不要主动扣,要"看表算差"

▌ 直觉写法(错的)
    while (1) {
        Sleep(8000);
        memory_zhi--;
    }
    → Sleep 期间程序完全冻结,按键和动画全都失效。

▌ 正确写法:钟表逻辑
    · 记下"上次扣的时刻" memory_last
    · 主循环里定期看一眼当前时刻 now
    · 如果 now - memory_last >= 8000 → 扣一点,更新 memory_last

▌ 为什么用"差值"而不是"计数器"
    计数器写法:每一帧 counter++, 到 160 就扣一点
    → 依赖循环频率必须准确,任何延迟都会漂移。

    差值写法:直接问 Windows 表 GetTickCount()
    → 不管循环快慢,只看真实时间过了多少 —— 精准可靠。


============================================================
【三、GetTickCount 是什么】
============================================================

▌ 它是 Windows 提供的一个函数
    #include <windows.h>
    DWORD GetTickCount();

▌ 返回值
    从电脑开机到现在的毫秒数(DWORD = unsigned long = 32 位无符号整数)
    · 开机 1 秒 → 返回约 1000
    · 开机 1 分钟 → 返回约 60000
    · 开机 1 小时 → 返回约 3600000

▌ 用法:两次相减 = 时长
    DWORD a = GetTickCount();
    (做些事情)
    DWORD b = GetTickCount();
    DWORD 差 = b - a;              // 中间过了 差 毫秒


============================================================
【四、主循环改造:_getch → _kbhit + _getch】
============================================================

▌ 原来的主循环(有阻塞)
    while (1) {
        画屏幕
        char c = _getch();     // ← 卡住,等玩家按键
        处理 c
    }
    问题:_getch 卡住 → update_memory 一次都没机会跑
         → 记忆值永远不变

▌ 改造后
    while (1) {
        画屏幕
        draw_memory_secene();
        while (!_kbhit()) {           // 没键就转圈
            Sleep(50);
            int r = now_time();       // 看表
            if (r == -1) 触发结局 C
            if (r == 1) 重画 HUD
        }
        char c = _getch();            // 有键了取出来
        处理 c
    }

▌ 为什么 Sleep(50)
    · 每 50ms 看一眼有没有键 → 玩家感觉不到延迟
    · 每 50ms 看一眼表 → 每 8 秒扣一次误差最多 50ms
    · CPU 睡 50ms 时几乎不占资源 → 电脑不烧

    50ms 是"人感觉不到 + 电脑不烧"的甜蜜点。
    这个技巧笔记 20 (_kbhit 和 _getch)里已经学过。


============================================================
【五、暂停机制:栈】
============================================================

▌ 为什么需要暂停
    看幕间散文的 90 秒不该扣记忆值。
    看物品对话的 30 秒不该扣。
    章节过场的 8 秒不该扣。

▌ 简单方案(bool)的问题
    int paused = 0;
    进幕间:paused = 1;
    出幕间:paused = 0;

    now_time() 里 if (paused) return 0;
    → 看起来行,但记忆漏刷 90 秒后:
      now - memory_last = 90000 → 一口气扣 11 点
    → 幕间那 90 秒被算成走路时间了

▌ 正确方案:补偿时间
    暂停开始时记下时刻 pause_start
    暂停结束时算 pause_duration = now - pause_start
    然后 memory_last += pause_duration
    → 把"上次扣减时刻"往未来推 90 秒
    → 等效于"这 90 秒不算数"

    ★ 关键公式:memory_last += pause_duration
    ★ 意义:时间基准往后挪 = 那段时间跳过

▌ 为什么用栈
    严格来说,单个变量就够了 —— 你的游戏里不嵌套。
    用栈是为了:
      · 未来可能出现"幕间里再弹对话"这种嵌套
      · 答辩时能讲栈的 LIFO 特性
      · 练习数据结构

    栈的规则:
      push:进入暂停(记下这一刻)
      pop:退出暂停(如果栈变空,才真正补偿时间)


============================================================
【六、系统的六个函数 + 五个变量】
============================================================

▌ 变量
    int memory_zhi = 100;             当前记忆值 (0..100)
    DWORD memory_time = 8000;         扣减周期 (8 秒)
    DWORD memory_last = 0;            上次扣减时刻
    DWORD time_zone[15];              暂停栈:15 个 DWORD 数组
    int time_top = 0;                 栈顶指针

▌ 函数
    memory_clorur(int x)              数值到颜色的映射
                                      · >=60 白 · >=30 黄 · <30 红
    draw_memory_secene()              画 HUD 到屏幕右上角
    create_time()                     初始化系统(main 里调一次)
    push_stack_time()                 push:进入暂停
    pop_stack_time()                  pop:退出暂停(可能触发补偿)
    now_time()                        每 50ms 调一次,返回 0/1/-1
                                      · 0:没变化
                                      · 1:扣了一点(需重画 HUD)
                                      · -1:归零(触发结局 C)


============================================================
【七、暂停栈的两个关键规则】
============================================================

▌ 规则 1:push 和 pop 严格配对
    进入 4 个特殊函数时 push,退出时 pop。
    对应:
      play_pangpai(章节过场)      → push / pop
      play_the_pangbai(幕间散文)   → push / pop
      playconversation(物品对话)   → push / pop
      begin_conver_history(回看)   → push / pop

    ★ 提前 return 时也必须 pop
      → 见 bug 记录 10 · 错误 ⑧⑨⑩

▌ 规则 2:只有栈完全空才补偿时间
    嵌套暂停时:
      最外层 push → 栈: [10000]           ← 暂停开始
      内层 push   → 栈: [10000, 12000]    ← 嵌套
      内层 pop    → 栈: [10000]           ← 还在暂停中
      最外层 pop  → 栈: []                ← 真正结束

    只有最后一次 pop 让栈变空时,才用 GetTickCount - time_zone[0]
    计算总暂停时长,把 memory_last 往后推。

    ★ 中间的 pop 什么都不做(除了 top--)。


============================================================
【八、now_time 函数详解】
============================================================

▌ 完整逻辑
    int now_time() {
        int flag = 0;
        if (memory_zhi <= 0) return 0;        (1) 已归零,不再动
        if (time_top > 0) return 0;           (2) 暂停中,不扣
        DWORD temp = GetTickCount();
        while (temp - memory_last >= memory_time && memory_zhi > 0) {
            memory_zhi--;                     (3) 扣一点
            memory_last += memory_time;       (4) 时刻按理想周期递增
            flag = 1;                         (5) 标记"扣过了"
        }
        if (memory_zhi == 0) return -1;       (6) 刚归零 → 结局 C
        return flag;                          (7) 返回 0 或 1
    }

▌ 为什么用 while 不用 if
    假设玩家挂机 30 秒(每 8 秒 1 点):
      · 用 if:一次调用只扣 1 点 → 30 秒只扣 1 点(错)
      · 用 while:循环里连扣 3 点 → 每 8 秒 1 点(对)

▌ 为什么 memory_last += memory_time 而不是 = now
    · 用 += memory_time:严格按 8000 递增,永远不漂移
    · 用 = now:每次追当前时钟,累积误差,越走越慢

    这是"离散时钟"的经典写法:基准按理想周期前进,
    不追物理时钟。


============================================================
【九、暂停栈的 push/pop 详解】
============================================================

▌ push_stack_time()
    void push_stack_time() {
        if (time_top < 15) {
            time_zone[time_top] = GetTickCount();
            time_top++;
        }
    }
    · 检查栈没满(防越界)
    · 记录当前时刻到栈顶
    · 栈顶指针 +1
    · ★ 写数据和 top++ 必须绑在一起

▌ pop_stack_time()
    void pop_stack_time() {
        if (time_top <= 0) return;
        time_top--;
        if (time_top == 0) {
            DWORD temp = GetTickCount() - time_zone[0];
            memory_last = memory_last + temp;
        }
    }
    · 栈已空则直接返回(防御性)
    · 栈顶 -1
    · 只有栈完全空 → 用 time_zone[0](最外层暂停开始时刻)
      计算总暂停时长
    · 补偿到 memory_last

    ★ 关键:用 time_zone[0] 不是 time_zone[time_top]
      · 最外层的 push 时刻永远在数组第 0 位
      · 意图明确 —— 见 bug 10 · 错误 ⑥

【十、HUD 三段颜色 + 文字】
============================================================

▌ 视觉分级
    100~60 → 白(15)  · 无提示词    · "安全"
    59~30  → 黄(14)  · "· 模糊"    · "提醒"
    29~0   → 红(12)  · "· 消散"    · "危险"

▌ printf 格式
    printf("记忆 %03d / 100      ", memory_zhi);  白
    printf("记忆 %03d / 100 · 模糊", memory_zhi);  黄
    printf("记忆 %03d / 100 · 消散", memory_zhi);  红

▌ 为什么用 %03d
    · %d:100 是 3 位,87 是 2 位,8 是 1 位 → 宽度不一致,
          残留字符
    · %03d:永远 3 位,不够补零(087, 008, 100)→ 屏幕干净

▌ 为什么白色版本后面加空格
    从"87 · 模糊"变到"90       "时,后面的空格能覆盖旧的"· 模糊"
    (虽然记忆值只降不升,理论上不会往回变,但保险起见)

【十一、时间参数的选择】
============================================================

▌ 参数:MEMORY_TICK_MS = 8000
    每 8 秒扣 1 点 → 归零总时长 800 秒 ≈ 13 分 20 秒

▌ 为什么是 8 秒
    单场景玩家用时估算:
      章节过场:8 秒
      幕间散文:80 秒
      拾取 3 件物品:100 秒
      回 hall:20 秒
      → 单场景约 200 秒

    全流程:6 章 × 200 秒 = 1200 秒 ≈ 20 分钟

    但幕间/对话不扣,实际扣值时间约:
      每章走路 100 秒 × 6 章 = 600 秒纯走路
      → 扣 600/8 = 75 点
      → 起始 100 - 结束 25(红色警戒区)

    这样有紧张感,但不会 GG。

▌ 如果测试后觉得难度不对
    · 太紧 → 改 10000 或 12000
    · 太松 → 改 5000
    · 只改这一个常量,其他不动

【十二、"钟表逻辑"这套思路的通用性】
============================================================

▌ 这套技巧不只是记忆值可以用
    任何"每 N 秒/毫秒发生一次"的事件都可以用它:
      · 动画帧切换
      · 敌人 AI 决策
      · 定时刷新 BGM 强度
      · 自动存档(每 60 秒)
      · 提示气泡(3 秒后消失)

▌ 模板
    DWORD last_tick = 0;
    const DWORD PERIOD_MS = ...;

    void init() { last_tick = GetTickCount(); }

    int should_trigger() {
        DWORD now = GetTickCount();
        if (now - last_tick >= PERIOD_MS) {
            last_tick += PERIOD_MS;
            return 1;
        }
        return 0;
    }

    主循环:
        if (should_trigger()) {
            触发那件事;
        }

【十四、答辩问答】
============================================================

Q1: 记忆值系统的核心思路?
    钟表逻辑:记下上次扣减时刻,主循环每 50ms 看表算差,
    差够 8000 就扣。不阻塞、不漂移、可暂停。

Q2: 为什么不用 Sleep(8000) 直接睡?
    Sleep 期间程序冻结,按键和动画都失效。用 GetTickCount
    差值法可以在主循环里边等边算,不影响响应速度。

Q3: 暂停机制怎么实现的?
    用栈记录"每次暂停开始的时刻"。push/pop 严格配对。
    只有栈完全空时,把总暂停时长补偿到 memory_last,
    等效于"暂停期间的时间不算数"。

Q4: 为什么用栈不用一个变量?
    支持嵌套暂停。虽然当前游戏不嵌套,但栈的写法更健壮 ——
    如果以后加"幕间里再弹对话"这种嵌套场景,不用改代码。

Q5: memory_last += memory_time 和 memory_last = now 有什么区别?
    前者按理想周期递增,不漂移。后者会累积循环误差,
    时间越走越慢。经典的"离散时钟"陷阱。

Q6: %03d 是什么意思?
    printf 格式化:3 位宽,不够用 0 补齐。防止 100→99→8 时
    数字宽度变化,屏幕残留字符。

Q7: 记忆值归零后发生什么?
    now_time 返回 -1 → 主循环跳出 → 触发 play_ending_C()。
    结局 C 是"星尘归海"(遗忘结局),独白讲"你已经分不清哪一
    颗星星是她"。
