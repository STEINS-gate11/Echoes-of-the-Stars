学习笔记 26 · 字符列宽判断(< 0x80 vs >= 0x80)
============================================================

【时间】2026-07-31
【学到什么】
  · 怎么判断一个宽字符在屏幕上占几列
  · 半角 vs 全角
  · 0x80 这个阈值的意义

============================================================
【核心代码】
============================================================

  if (text[i] < 0x80) col_w = 1;
  else col_w = 2;

  含义:
    · Unicode 编码 < 0x80(128)· 1 列
    · Unicode 编码 >= 0x80· 2 列

============================================================
【0x80 是什么】
============================================================

  0x80 = 128(十进制)

  ASCII 字符表只用了 0x00..0x7F(0..127)
  0x80(128)开始是扩展字符
  中文 / 日文 / 韩文都在 0x80 以上

  所以:
    < 0x80  → 一定是 ASCII → 1 列
    >= 0x80 → 一定是中文/全角 → 2 列

============================================================
【哪些字符 1 列(ASCII)】
============================================================

  英文 a-z A-Z        1 列
  数字 0-9             1 列
  半角空格             1 列
  半角标点 . , ! ? :   1 列
  半角引号 " '          1 列
  半角括号 ( ) [ ]     1 列
  半角斜杠 / \         1 列

============================================================
【哪些字符 2 列(全角)】
============================================================

  中文 一二三四五        2 列
  中文标点 。,;:!?——     2 列
  中文引号 “”‘’         2 列
  中文括号 （）          2 列
  日文 ひらがな          2 列
  韩文 한글             2 列
  emoji(整体)           2 列

============================================================
【emoji 特殊情况 · 代理对】
============================================================

  emoji 实际是 2 个 wchar_t(高代理位 + 低代理位)
  例:
    📖 = wchar_t 0xD83D + wchar_t 0xDCD6
    ⭐ = wchar_t 0xD83C + wchar_t 0xDF20

  但在屏幕上只占 2 列

  我们用 text[i] < 0x80 判断:
    0xD83D >= 0x80 → col_w = 2

  col_w=2 是对的(整个 emoji 占 2 列)
  但 i 一次 +1 → 第一次进 0xD83D(高代理位)· 第二次进 0xDCD6(低代理位)
  两次 col_w 都 +2 → 总共 +4 → 错了!实际只占 2

  真正的处理:
    遇到高代理位(0xD800-0xDBFF)→ 跳过下一个低代理位
    col_w 只 +2 一次(不重复加)

  但 print_with_wrap 里:
    0xD83D >= 0x80 → col_w=2
    写 WriteConsoleW(高代理位)· 光标自己推
    0xDCD6 >= 0x80 → col_w=2
    写 WriteConsoleW(低代理位)· 光标自己推
    cur_x += 2 · 再 +2
    实际光标只推了 2 列 · 但我们记 4 列

  结果:emoji 后面的字符位置错!
  错位距离 = 2(因为多算 2 列)

  解决(目前没做):
    遇到高代理位时,i 不 +1 而是 +2
    跳过低代理位
    col_w 只 +2 一次

============================================================
【为什么需要 col_w】
============================================================

  用于换行判断:
    if (cur_cols + col_w > max_cols) {
        // 换行
    }

  没有 col_w 就不知道什么时候该换行
  · 太早换行 → 短句也换
  · 太晚换行 → 字符撞右边

============================================================
【替代方案】
============================================================

  也可以用 iswascii():
    if (iswascii(text[i])) col_w = 1;
    else col_w = 2;

  iswascii() 在 ctype.h 里
  效果和 < 0x80 一样 · 但更标准

  也可用 iswprint() 检查是否可打印:
    if (iswprint(text[i]) && ...) col_w = ??;
  iswprint 不直接告诉列宽 · 不太适合

  最简单还是 < 0x80。

============================================================
【测试方法】
============================================================

  写个测试看:
    L"a你b中c" = 5 字符
    ASCII a=1, 你=2, b=1, 中=2, c=1
    总列宽 = 1+2+1+2+1 = 7

  max_cols=7 时:
    打 'a' cur_cols=1
    打 '你' cur_cols=3
    打 'b' cur_cols=4
    打 '中' cur_cols=6
    打 'c' 6+1=7 不超 7 → 同行

  max_cols=6 时:
    打完 '中' cur_cols=6
    打 'c' 6+1=7 > 6 → 换行
    c 在新行
