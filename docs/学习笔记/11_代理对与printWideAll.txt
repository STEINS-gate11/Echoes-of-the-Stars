============================================================
【一、Unicode 基本平面与补充平面】
============================================================

Unicode 把所有字符按编号安排。

  基本多语言平面 BMP：编号 U+0000 到 U+FFFF
  补充平面：编号 U+10000 到 U+10FFFF

在 Windows 使用的 UTF-16 表示法中：

  基本平面字符 → 1 个 wchar_t
  补充平面字符 → 2 个 wchar_t（叫"代理对"）


============================================================
【二、常见字符归属】
============================================================

一个 wchar_t：

  普通汉字        「你」「星」「照」
  标点            「，」「。」
  基础符号        「★」「✦」「○」
  部分 emoji      ⭐（U+2B50）

两个 wchar_t（代理对）：

  多数 emoji      🖼 (U+1F5BC)
                  📖 (U+1F4D6)
                  📚 (U+1F4DA)
                  📸 (U+1F4F8)
                  🎵 (U+1F3B5)
                  📱 (U+1F4F1)
                  💊 (U+1F48A)
                  🎫 (U+1F3AB)
                  💌 (U+1F48C)
                  🌠 (U+1F320)

判断方法（不用背，够用就行）：

  ★ 大部分你在手机 emoji 键盘里挑到的 emoji 都是代理对。
  ★ 基础符号（★✦●⭐）多数是单个 wchar_t。


============================================================
【三、为什么打字机会把 emoji 拆开】
============================================================

delay_with_Chinese 每次输出 1 个 wchar_t：

  WriteConsoleW(output, &text[i], 1, &written, NULL);

对于普通中文：

  「你」= 1 个 wchar_t
  一次输出 → 完整显示

对于代理对 emoji：

  🖼 = 0xD83D 0xDDBC     2 个 wchar_t

  第 1 次输出 0xD83D  → 屏幕出现乱码或方框
  第 2 次输出 0xDDBC  → 屏幕出现乱码或方框

结果：

  屏幕看到两个乱码，而不是一个 🖼


============================================================
【四、解决办法：一次交出整段字符串】
============================================================

如果一次把整段字符串交给 WriteConsoleW，
Windows 内部会正确识别代理对，不再拆开。

代码：

  void printWideAll(const wchar_t* text) {
      HANDLE output = GetStdHandle(STD_OUTPUT_HANDLE);
      DWORD written;

      int len = 0;
      while (text[len] != L'\0') {
          len++;
      }

      WriteConsoleW(output, text, len, &written, NULL);
  }

关键差别：

  delay_with_Chinese  每次 WriteConsoleW 输出 1 个 wchar_t
  printWideAll        一次 WriteConsoleW 输出所有 wchar_t


============================================================
【五、两种函数的分工】
============================================================

  场景                需要逐字动画   会出现 emoji     使用
  ------------------- -------------- --------------- -------------------
  姓名栏              否             是（代理对）     printWideAll
  对话正文            是             否               delay_with_Chinese
  层间旁白            是             否               delay_with_Chinese
  结局标题            否             可能             printWideAll

原则：

  只要文本里可能含 emoji 或者其他补充平面字符
  → 用 printWideAll
  否则可以放心用 delay_with_Chinese


============================================================
【六、为什么不改造 delay_with_Chinese】
============================================================

理论上可以：

  if 当前 wchar_t 是高代理  → 一次输出 2 个 wchar_t
  else                       → 输出 1 个

但涉及"高代理范围判断" 0xD800 到 0xDBFF，需要位比较。
你还没学位运算，暂时不用改造。

分工方案（printWideAll + delay_with_Chinese）能覆盖所有场景。


============================================================
【七、你现在需要理解的部分】
============================================================

必须理解：

  1. 代理对是 UTF-16 表示部分 emoji 时用的两个 wchar_t
  2. delay_with_Chinese 每次只输出 1 个 wchar_t
  3. 一次只输出 1 个 wchar_t 会拆开代理对
  4. printWideAll 一次把整段交给 WriteConsoleW，代理对不会被拆开

暂时不需要理解：

  - 具体高代理和低代理的编号范围
  - 位运算判断代理
  - UTF-16 每种编码的字节结构


============================================================
【八、一句话总结】
============================================================

代理对：

  部分 emoji 由 2 个 wchar_t 组成一个字符。

打字机：

  每次输出 1 个 wchar_t → 会把代理对拆开。

对策：

  姓名栏用 printWideAll 整段输出（代理对不会被拆开）
  正文继续 delay_with_Chinese 逐字动画


============================================================
【九、为什么 printWideAll 里要先算长度】
============================================================

看这段：

  int len = 0;
  while (text[len] != L'\0') {
      len++;
  }

它在做的事：

  数一下这段宽字符串一共几个 wchar_t

之所以必须自己数，是因为 WriteConsoleW 的第三个参数：

  nNumberOfCharsToWrite

必须明确告诉它一次输出几个 wchar_t。

WriteConsoleW 不看 \0：

  WriteConsoleW(handle, text, 5, &written, NULL);
  → 一次输出 5 个 wchar_t，无论有没有 \0

传大了 → 会输出到 \0 之后的垃圾数据
传小了 → 字符串被截断

所以调用之前必须先"数清楚"字符个数。


对比 printf：

  printf("%s", text);
    printf 遇到 \0 会自动停止

  WriteConsoleW(handle, text, n, ...);
    只看你传入的字符个数 n，不看 \0


也可以用库函数：

  #include <wchar.h>

  int len = (int)wcslen(text);
  WriteConsoleW(output, text, len, &written, NULL);

wcslen 就是"给宽字符串数长度"的库函数。

手写循环和 wcslen 效果一样：

  int len = 0;
  while (text[len] != L'\0') len++;

  等价于

  int len = (int)wcslen(text);

之所以先用循环写，是不想让你临时又多学一个函数。


============================================================
【十、printWideAll 逐行含义】
============================================================

HANDLE output = GetStdHandle(STD_OUTPUT_HANDLE);
    获取控制台的"把手"，告诉 Windows 要写到哪个屏幕

DWORD written;
    用于接收 WriteConsoleW 实际写了多少个 wchar_t
    我们不主动读它，但接口要求提供这个变量的地址

int len = 0;
while (text[len] != L'\0') {
    len++;
}
    从头往后数，直到遇到 \0 结束符
    len 即为这段宽字符串的字符数

WriteConsoleW(output, text, len, &written, NULL);
    一次性把整段字符串交给 Windows
    Windows 内部识别代理对，正确渲染


============================================================
【十一、举例：一段宽字符串的内存布局】
============================================================

const wchar_t* text = L"📖 空白日记本";

在 Windows UTF-16 里大致是：

  0xD83D  ← 📖 高代理
  0xDE96  ← 📖 低代理
  L' '    ← 空格
  L'空'
  L'白'
  L'日'
  L'记'
  L'本'
  L'\0'   ← 结束符

数一下（不含 \0），共 8 个 wchar_t。

循环跑完：

  len = 8

调用：

  WriteConsoleW(output, text, 8, &written, NULL);

Windows 拿到 8 个 wchar_t：

  第 1、2 个   → 组合成 📖（代理对）
  第 3 个      → 空格
  第 4 ~ 8 个  → 5 个汉字

正确渲染。


============================================================
【十二、为什么不能像 delay_with_Chinese 每次一个 wchar_t】
============================================================

delay_with_Chinese 内部：

  for (int i = 0; text[i] != L'\0'; i++) {
      WriteConsoleW(output, &text[i], 1, &written, NULL);
      Sleep(times);
  }

每次只输出 1 个 wchar_t。

对于 📖 = 0xD83D + 0xDE96：

  第 1 次输出 0xD83D    → 屏幕上是乱码或方框（半个 emoji）
  第 2 次输出 0xDE96    → 屏幕上又是乱码或方框（另一半）

Windows 拿到"半个 emoji"没有办法正确渲染，
只能当作两个无效字符处理。

printWideAll 一次交出 8 个 wchar_t：

  Windows 内部知道 0xD83D 是高代理，
  会自动组合下一个 0xDE96 成为一个完整 emoji。

关键差别：

  逐个 wchar_t 输出：代理对被拆开 → 乱码
  一次整段输出   ：Windows 自己组合 → 正常显示


============================================================
【十三、一句话记住 printWideAll 的两件事】
============================================================

1. 它必须先算字符个数：

   因为 WriteConsoleW 不像 printf 会自动停在 \0。

2. 它必须一次输出整段：

   因为 emoji 代理对由 2 个 wchar_t 组成，
   只有一次交出整段，Windows 才能正确组合。
