============================================================
《星空回响》学习笔记 08 · 键盘输入缓冲区与 clearInputBuffer
============================================================

【学习时间】2026-07-21

【本笔记内容】
- 控制台输入缓冲区是什么
- _kbhit() 与 _getch() 的区别
- 为什么打字机播放期间的按键会影响后续对话
- clearInputBuffer() 为什么使用 while
- 正确的对话等待顺序


============================================================
【一、什么是控制台输入缓冲区】
============================================================

玩家按下键盘后，按键不一定立即被程序处理。

Windows 会先把尚未读取的按键暂存在一个区域中：

  控制台输入缓冲区

程序调用 _getch() 时，才从缓冲区里取出一个按键。

如果缓冲区为空，_getch() 会等待玩家按键。
如果缓冲区已有按键，_getch() 会立即返回，不会等待。


============================================================
【二、为什么打字机期间会残留按键】
============================================================

打字机播放期间，程序正在反复执行：

  WriteConsoleW(...);
  Sleep(delayMs);

这段时间没有调用 _getch()，但玩家仍然可以按键。

例如玩家在文字播放时连续按了三次空格：

  [空格][空格][空格]

这些按键会进入输入缓冲区等待读取。

文字播放结束后执行：

  _getch();

_getch() 会立即取出之前残留的空格，因此对话直接关闭。

这不是编译错误，而是输入时序造成的交互 Bug。


============================================================
【三、_kbhit() 是什么】
============================================================

需要头文件：

  #include <conio.h>

用法：

  _kbhit()

作用：

  检查控制台输入缓冲区里有没有按键。

返回值：

  0       没有按键
  非 0    有按键

重要特点：

  - 不会暂停程序；
  - 只负责检查；
  - 不会取走按键。

例子：

  if (_kbhit()) {
      printf("缓冲区中有按键");
  }


============================================================
【四、_getch() 在清理函数中的作用】
============================================================

普通用法：

  char c = _getch();

读取一个按键，并保存到变量 c。

清理时：

  _getch();

读取一个按键，但不保存返回值，相当于：

  取出一个旧按键，然后丢弃。


============================================================
【五、clearInputBuffer() 函数】
============================================================

void clearInputBuffer() {
    while (_kbhit()) {
        _getch();
    }
}

作用：

  只要输入缓冲区里还有旧按键，就不断读取并丢弃，
  直到输入缓冲区彻底为空。


============================================================
【六、逐行运行过程】
============================================================

假设缓冲区中有三个空格：

  [空格][空格][空格]

第 1 轮：

  _kbhit() 返回非 0
  _getch() 丢掉一个空格
  剩余：[空格][空格]

第 2 轮：

  _kbhit() 返回非 0
  _getch() 丢掉一个空格
  剩余：[空格]

第 3 轮：

  _kbhit() 返回非 0
  _getch() 丢掉最后一个空格
  剩余：空

第 4 次检查：

  _kbhit() 返回 0
  while 循环结束


============================================================
【七、为什么必须使用 while】
============================================================

如果只写：

  if (_kbhit()) {
      _getch();
  }

最多只能清除一个按键。

玩家提前按了三次键时，仍会留下两个旧按键。

使用 while：

  while (_kbhit()) {
      _getch();
  }

才能把任意数量的旧按键全部清掉。


============================================================
【八、为什么清理必须放在播放之后】
============================================================

错误顺序：

  clearInputBuffer();
  delay_with_Chinese(L"对话", 80);
  _getch();

问题：

  清理之后，玩家仍可以在打字机播放期间按键，
  新按键又会进入缓冲区。

正确顺序：

  delay_with_Chinese(L"对话", 80);
  delay_with_Chinese(L"按任意键继续……", 50);

  clearInputBuffer();
  _getch();

含义：

  1. 完整播放文字；
  2. 清除播放期间积累的旧输入；
  3. 等待玩家重新按下一个新键；
  4. 关闭对话。


============================================================
【九、与项目设计的关系】
============================================================

项目已经确定：

  不提供打字机快进。

因此必须保证：

  - 打字期间按键无效；
  - 文字必须完整播放；
  - 播放结束后必须重新按键才能继续。

clearInputBuffer() 用来落实这条规则。


============================================================
【十、三个函数的区别】
============================================================

  _kbhit()
    检查有没有按键
    不等待
    不取走按键

  _getch()
    读取一个按键
    缓冲区为空时会等待
    读取后该按键从缓冲区消失

  clearInputBuffer()
    自己封装的函数
    循环使用 _kbhit() 和 _getch()
    清空所有尚未处理的旧按键


============================================================
【十一、一句话记住】
============================================================

  while (_kbhit()) {
      _getch();
  }

意思是：

  只要输入缓冲区里还有旧按键，
  就不断读出并丢弃，直到清空。

对话正确顺序：

  播放文字 → 清旧输入 → 等新按键 → 关闭对话
