【一、遇到的问题】
============================================================

写代码时定义了一个墙表：

  const char* the_chapter_Walls[7] = { "=D", "=", "=[]#", ... };

然后写：

  char* curr = the_chapter_Walls[cur_chapter];   // ← 编译报错

VS 报错："const char* 不能转换成 char*"。

到底啥意思？


============================================================
【二、字符串字面量是"只读"的】
============================================================

在 C 里，当你写：

  "=D"
  L"⭐ 折纸星星"

编译器会把这段文字放在【只读数据段】里。程序运行时这段
内存是"只能读，不能写"的 —— 如果你试着改，程序会崩。

  const char* p = "hello";
  p[0] = 'H';              // 运行时会崩！

正因为这样，C 强制要求：所有指向字符串字面量的指针，
必须是 const char* 类型。

  const char* 意思是：这个指针指向的字符是只读的。


============================================================
【三、char* 和 const char* 的区别】
============================================================

  char*         : 我可以通过它读，也可以通过它改
  const char*   : 我只能通过它读，改不了

类比：
  char*       = 【可读写的小水桶】—— 你可以随便倒水
  const char* = 【只读的玻璃罐】  —— 你只能看，不能倒出来

规则：
  ┌────────────────────────────────────────┐
  │ 玻璃罐 → 玻璃罐 : OK                    │
  │ 小水桶 → 小水桶 : OK                    │
  │ 玻璃罐 → 小水桶 : ✗ 编译报错             │
  │   （怕你后面偷偷倒出来）                 │
  │ 小水桶 → 玻璃罐 : OK                    │
  │   （承诺"我不倒"没问题）                 │
  └────────────────────────────────────────┘


============================================================
【四、什么时候必须加 const】
============================================================

★ 只要等号右边是字符串字面量或已经是 const 的指针，
   等号左边就必须加 const。

例 1：局部变量接字符串
  const char* curr = the_chapter_Walls[i];   ✓
  char*       curr = the_chapter_Walls[i];   ✗ 编译错

例 2：结构体字段
  struct Item {
      const wchar_t* name;         ✓  用 L"..." 初始化 OK
      wchar_t*       name;         ✗  用 L"..." 初始化会警告
  };

例 3：函数参数
  void print(const char* s);       ✓  可以传 "hello"
  void print(char* s);             ✗  传 "hello" 会警告

  （反过来 char* 可以传给 const char* 参数，
    因为 "我只读不改" 是更强的承诺）

例 4：数组
  const char* names[7] = { "=D", "=", ... };   ✓
  char*       names[7] = { "=D", "=", ... };   ✗

【五、写代码顺口溜】
============================================================

  看到 " ... "  →  必须用 const 指针接

  const wchar_t*   name = L"...";

============================================================
【六、编译时报错怎么判断】
============================================================

VS 报错常见几种：

  "cannot convert from 'const char*' to 'char*'"
  → 少加了 const，在等号左边加

  "cannot convert from 'const wchar_t*' to 'wchar_t*'"
  → 同上，wchar_t 版本

  "read-only variable is not assignable"
  → 你尝试改一个 const 变量，去掉赋值或改数据源

  一律加 const 就对了。


============================================================
【七、常见误区】
============================================================

误区 1：加了 const 会不会性能差？
    不会。const 只是编译期检查，运行时代码完全一样。

误区 2：只有字符串要用 const？
    不是。任何"只读"的东西都可以加 const。但项目里
    最常见的还是字符串。

误区 3：加了 const 就不能改指针本身？
    不对。const char* p，意思是"p 指向的字符不能改"，
    但 p 自己可以改指向别的字符串：

      const char* p = "hello";
      p = "world";              // OK！改的是指针值
      p[0] = 'X';               // 错！改的是指向的字符

    （"指向不变" 是另一种写法：char* const p，很少用）


============================================================
【八、答辩问答】
============================================================

Q1：为什么代码里到处都有 const？
    因为字符串字面量在只读数据段，必须用 const 指针接。
    加了 const 编译器会帮我检查"没有意外修改字符串"。

Q2：加 const 有开销吗？
    没有。const 是编译期检查，运行时完全没影响。

Q3：什么时候不用 const？
    需要写入的内存不用。比如 char bg[20][50] 是数组，
    我们要往里面写，就不加 const。
